# M0 —— 仓库脚手架 + test-support + cordis 最小启动

- **状态**：`proposed`（当前里程碑，待开始）
- **前置**：无。仓库现有内容：`README.md`、`docs/requirements.md`、`.agents/`。
- **依赖关系**：M0 是地基 —— 之后每个 M 都建立在"能组装 ctx、能写测试"的前提上。没有 M0，M1 的事件日志无法注入测试服务，M2 的假 LLM 无处挂载。

## 目标

建立 monorepo 骨架，让"空 profile 能被 cordis 组装起来"，并用测试验证组装行为。这是全项目第一次证明"一切皆为插件"可以落地。

## 任务拆解（按 TDD 顺序）

### 0. 上游参考基座

- 按 `docs/references/upstream.md` 把上游 clone 到仓库外：`git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git ../deepseek-harness-upstream`。
- 校对 `docs/references/upstream.md` 的路径索引（本地安装路径、克隆路径是否与文档一致），不一致则更新。
- 本任务不适用红绿循环（环境准备）。

### 1. 仓库脚手架

- pnpm workspaces monorepo；包 scope `@mini-dsh/*`。
- 根 tsconfig（严格模式），各包 tsconfig 继承。
- Vitest：先写"测试能运行"的失败测试（RED），再完成配置让它通过（GREEN）。

### 2. `packages/test-support`

教学定位：全项目测试的公共语言，之后的每个 seam 契约测试都建立在它上面。

- 提供：创建测试 ctx（基于 cordis）、注入测试服务、事件断言工具。
- 假 LLM 不在本 M（M2 再做），但包结构与命名要预留位置。
- 本包自己的测试：用测试 ctx 断言"注入的服务能取到、事件能收到"。

### 3. `packages/kernel`

- `loadProfile(path)`：读 `profile.yml` 列出的插件行 → 用 cordis 组装 ctx → 启动。
- **只用官方 `cordis` npm 包**；本包不实现任何"内核"逻辑（硬约束 §2.1）。
- `profile.yml` 最小格式：`plugins:` 列表，每行 `name` + 可选 `options`。
- 测试：空 profile 能启动；带一个测试插件行的 profile 启动后服务可注入。

### 4. 提交纪律

每步 commit：RED 提交 → GREEN 提交 → REFACTOR 提交，中文 commit message（TDD skill 规定）。

## 教程交付（requirements §5.1）

`docs/tutorials/M0-kernel-and-plugins.md`：

- **动机**：为什么先做内核与组装、monorepo 怎么支撑"一切皆为插件"
- **新概念**（首次出现，从零解释）：CORDIS、ctx、服务（service）、事件（event）、插件、profile 组合、monorepo、seam
- **tradeoff**：为什么用官方 cordis 而不是手写内核；为什么 test-support 要先于业务包；为什么 profile 用 yml 列表而不是代码硬编码
- **动手练习**：给 profile 加一个自定义插件（监听/打印一条事件），零 API key 可跑
- 建立 `docs/tutorials/README.md` 索引
