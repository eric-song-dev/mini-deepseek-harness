# M5 —— Trajectory 简化视图 + skills 子系统

- **状态**：`implemented`（2026-08-16 实现并通过验收；决策核对与实施修订见
  `implemented/architecture/2026-08-16-m5-轨迹-与-skills-决策.md`）
- **前置**：M4（已完成）。依赖 M4 的：Slot seam（轨迹面板 = 再注册一个 slot，shell 不改）、
  事件桥与 client store（轨迹视图是同一份日志的又一个消费者）、`session/append`、
  Tools seam（skill 工具与 bash/fs 并列注册）。
- **依赖关系**：M0–M4 把"日志真源 → 投影"的原料与通道全部打通，M5 是 MVP 的收口——
  做"灵魂的最后一环"：**轨迹可回放**（requirements §4 硬约束"Trajectory 是灵魂"的兑现）
  与 **skills 自举**（mini 版能加载并运行自己的 TDD skill）。M5 之后 MVP 10 项全部完成。

## 目标

1. **Trajectory 简化视图**（requirements MVP #8）：把会话日志按**轮**分组渲染成事件表，
   点选任意事件在**检查器**里看全量载荷（token / 耗时 / 输入输出）。
2. **Skills 子系统**（requirements MVP #9）：`packages/skill` 提供 Skills seam
   （注册表 + filesystem 发现）+ `skill` 工具；**自举验收：mini 版能加载并运行
   自己的 TDD skill（`.agents/skills/tdd/SKILL.md`）**。

**验收：轨迹面板能回放 M4 里完成的对话（轮/事件/耗时/检查器）；`skill` 工具能加载 TDD skill。**

## 关键设计决策（预拍板，M5 开工时逐条核对）

1. **Trajectory 投影放 session 包**：`projectTurns(events)` 输出按轮分组结构
   （轮序号、user 文本、事件列表、起止 ts、耗时）。与 M2 的 `projectMessages`
   （输入侧）并列成"输出侧视图"——client、未来的 CLI、测试共用同一投影。
   "日志真源 → 投影 → 视图"三件套在代码上就是 session（投影）→ client（视图）。
2. **token 数据要落日志（M4 遗留）**：`assistant` 事件 payload 增**可选** `usage`
   （loop 把 `llm.chat` 返回的 `result.usage` 写进 assistant 事件）。旧日志（M2–M4）
   无此字段，投影兜底显示 `—`。耗时一律由事件 `ts` 差算出（tool 耗时 = 调用事件到
   结果事件的 ts 差）——不另存字段，不破坏 append-only。
3. **流式分片在轨迹里聚合展示**：一轮中的 `assistant/stream` 分片聚合成一条
   "assistant 正文（流式 ×n）"摘要行，点选可展开看逐片与拼接全文。token 级逐片
   回放动画放 v2（M4 已声明不做）。
4. **Skills seam**：`Skills` 抽象服务 = 注册表（register/list/get）+ filesystem 发现后端
   （目录约定：`<dir>/<name>/SKILL.md`，目录名即 skill 名，正文即内容）。换来源
   （远程市场、bundled）只换提供服务的插件。
5. **skill 工具是"文档检索"，不是 prompt 拼接**：`skill` 工具（tools seam 的一个普通
   工具，inject skills seam）让**模型按需调用**：列出技能 / 按名取技能全文返回给模型。
   不把全部 skill 塞进 system prompt（上下文成本 + 让模型自己决定何时需要——同 M3
   "工具声明走协议 tools 参数"的取舍）。loop 一行不改：注册进 toolRegistry 即可。
6. **ui-trajectory 走 M4 的 Slot 机制**：注册 slot `trajectory` → 进 M4 的 extras 区
   （全宽面板：左侧按轮事件表、右侧检查器）。shell 与 entry 一行不改——这正是
   M4 spec 决策 5 承诺的"未来任意 ui-* 插件从 Slot 挂进来"的第一次兑现。
7. **自举验收路径**：fakellm 台词本驱动 `skill` 工具加载 `tdd` skill（真 filesystem
   发现 `.agents/skills/tdd/SKILL.md`），断言模型收到的 skill 内容 == 文件正文；
   再跑一个"教模型按 TDD 说话"的最小对话 demo（skill 内容进了模型上下文）。

## 任务拆解（按 TDD 顺序）

### 1. session：assistant usage 词汇增量 + projectTurns 投影（RED→GREEN）

- `AssistantEventPayload` 增可选 `usage: ChatUsage`；loop 在 emit assistant 时带上
  `result.usage`（流式与非流式都带）。旧日志无此字段，投影兜底。
- `projectTurns(events)`：turn/start..turn/end 切块 → 每轮 `{ index, startedAt, endedAt,
  durationMs, events }` + 事件摘要（seq/type/ts/耗时/payload 摘要）；
  分片聚合（决策 3）；无配对 turn/start 的断尾按 M1 修复语义处理。
- 契约测试：M4 台词（工具往返 + 流式）投影出的轮结构逐字段断言。

### 2. packages/skill：Skills seam + filesystem 发现 + skill 工具（RED→GREEN）

- seam 契约测试（tests/contracts/）：register/list/get、未知 skill 报错、重复注册报错。
- filesystem 后端：扫描目录 → 每个 `<name>/SKILL.md` 一个 skill；不存在/坏目录的边界。
- `skill` 工具：声明 `{ name: 'skill', parameters: { action: 'list' | 'get', name? } }`，
  执行返回技能列表或技能全文（"输出是内容，异常是结果"——M3 工具语义）。
- 自举测试：真加载 `.agents/skills/tdd/SKILL.md`，断言内容一致。

### 3. client：ui-trajectory 插件（RED→GREEN，jsdom）

- 注册 slot `trajectory`：按轮分组事件表（轮号 / user 文本 / 事件数 / 耗时）+ 点选
  检查器（事件全量 payload JSON、token/耗时、tool 调用/结果对高亮配对）。
- 消费 `projectTurns(store.events)`；会话切换/resume 重投影；实时事件追加时表格更新。
- jsdom 测试：M4 台词（工具往返 + 流式）跑完一轮 → 断言表格行数、耗时非负、
  点选 tool 事件 → 检查器显示 input/output、usage 显示（新会话）/ `—`（旧日志 fixture）。

### 4. bundle-web：webBundle 增 uiTrajectory（RED→GREEN）

- 组合加一行；extras 区出现轨迹面板（shell 不改——M4 承诺的验证）。
- 构建冒烟仍绿。

### 5. 端到端（RED→GREEN）

- 轨迹回放：M4 的 e2e 台词（工具往返 + 流式）经真 host + 内存桥 + jsdom UI，
  轨迹面板完整回放（轮数/事件数/检查器）；旧日志 fixture 的 usage 兜底。
- skill 自举 e2e：真 host + 真 skill 工具 + fakellm 台词（先 list 再 get tdd），
  断言模型收到的上下文含 SKILL.md 正文。

### 6. demo + 教程

- `demo:trajectory`：跑一轮 M4 台词对话 + 打印/展示轨迹回放 + skill 自举一幕（零 key）。
- 教程 `docs/tutorials/M5-trajectory-and-skills.md` + 索引 + 小白验收。
