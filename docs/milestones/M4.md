# M4 —— Web：RPC 桥 + 会话列表 + composer + 流式 + tool 卡片

- **状态**：`proposed`（M3 收尾时定稿；进入 M4 前可再修订，修订记入 notes）
- **前置**：M3（已完成）。依赖 M3 的：SessionManager（create/resume/list 已就绪）、agent-loop
  句柄（`loop.chat` 是服务入口）、`tool` 事件词汇（M4 的 tool 卡片直接渲染 M3 落的调用/结果对）、
  Tools seam（浏览器侧不用，host 侧已接好）。M2 预留的 `ChatOptions.onChunk` 是流式的落点
  （M2 决策 1 已声明"流式预留，M4 接 UI 用同一 seam"）。
- **依赖关系**：M3 让 agent"会说也会做"，M4 让它"被人在浏览器里用起来"——同一套事件日志，
  从 `console.log` 的演示对象变成 Web 客户端渲染的内容。M5 的 Trajectory 视图在 M4 的
  client 框架（Slot 注册点）上再挂一个新面板。

## 目标

`packages/web` 提供 **host 服务**（Node HTTP + WebSocket，host↔client RPC 桥，requirements §4），
把 SessionManager / agent-loop 的能力暴露成远程操作：**列会话、新建、resume、发消息、收流式
增量、收事件**。`packages/client` 提供 **Client Slot seam**（UI 注册点，requirements §8）与
首批 UI 插件：会话列表、composer、流式消息、tool 卡片。`apps/web`（Vite entry 壳，只注入）
+ `packages/bundle-web`（web profile 组合）把它们排成一个能在浏览器里跑的应用。
**验收：浏览器里完成一次"真实对话"（假 LLM 驱动，零 key），tool 卡片随事件出现。**

## 关键设计决策（预拍板，M4 开工时逐条核对）

1. **桥的形态**：WebSocket 为唯一实时通道（HTTP 只做静态文件 + 升级握手）。client→host 发
   **请求**（带 requestId），host→client 推**事件**（`session/*`、`assistant/stream` 增量、
   通知）。RPC 方法最小集：`session.list` / `session.create` / `session.resume` / `session.send`
   （发用户消息，触发 loop）。这是原版 harness 的 RPC 桥的迷你教学版。
2. **桥是 seam**：`RpcBridge` 抽象（连接管理 + 请求分发 + 事件推送），host 侧生产实现是 WS，
   测试实现是内存直连（同进程零网络）。UI 插件只认"可注入的 client 连接"，不认 WebSocket——
   这样 client 组件测试零网络可跑。
3. **流式**：M2 预留的 `onChunk` 这次真正被消费：adapter 增 `stream: true` + SSE 行解析
   （`data: {...}` 分片）→ loop 把分片桥接成 `assistant/stream` 事件（词汇增量）→ 桥推给
   client → composer 区域增量渲染。假 LLM 增"流式分片序列"（M2 已留接口位）。
   非流式环境回退：host 收 `assistant` 终事件一次性渲染。
4. **loop 与桥的接法（定夺点 A）**：会话 ctx 上挂一个 host 侧适配插件（监听词汇事件 →
   桥推送；桥请求 → `loop.chat`），loop 本体不改。会话由 host 的 SessionManager 创建/resume
   并常驻（列表即内存会话表 + 磁盘元数据）。
5. **Client Slot seam**（requirements §8 的 UI 注册点）：client 插件按 `slot` 注册 UI 组件
   （`conversation` / `tool` / `session-list` / …），client-shell 按 slot 装配成页面。这是
   "一切皆为插件"在 UI 层的延续：未来任意 ui-* 插件都从 Slot 挂进来，不改 shell、不改桥。
6. **UI 框架**：React + Vite（requirements §4 已锁定）；React 组件通过薄封装注册成 Slot
   （Slot 注册表不依赖 React——框架只是第一个渲染实现）。
7. **测试环境拆分**：vitest 拆 workspace（M0 决策已预告）：node 侧（web/agent/session 等）
   与 jsdom 侧（client 组件）分开跑，互不污染环境。
8. **端到端验收路径（定夺点 B）**：`pnpm demo:web` 起真 HTTP+WS host（假 LLM 台词本含一次
   工具往返）+ Vite 页面，**人工在浏览器**完成"新建会话 → 发消息 → 看流式 → 看 tool 卡片"；
   自动化 e2e 用"真 host + 内存/脚本化 WS 客户端"全链路断言（不开真浏览器，浏览器人工验收
   交给 demo 与教程练习）。

## 任务拆解（按 TDD 顺序）

### 1. test-support 假 LLM 流式增量（RED→GREEN）

- 台词本支持 `chunks`（预设分片序列 + 每片延迟），调用 `onChunk` 逐片回调后 resolve 全文；
  与 toolCalls 回复互斥语义同 M3。断言"loop/桥收到的分片序列"。

### 2. adapter 流式增量（RED→GREEN）

- `onChunk` 传入时请求 `stream: true`，解析 SSE 行，逐分片回调（含 usage 收尾）；不传时
  行为与 M2/M3 完全一致（`stream: false`）。假 HTTP 端点支持流式 body 模拟。

### 3. `packages/web` host：RPC 桥 seam + HTTP/WS 服务（RED→GREEN）

- 契约测试：requestId 配对、事件推送保序、未知方法/坏载荷错误、断线清理。
- SessionManager 门面 RPC：list/create/resume/send；send 触发 loop，词汇事件实时推送。
- `assistant/stream` 事件词汇（session 包增量）与 onChunk 接线。

### 4. `packages/client`：Slot seam + 首批 UI（RED→GREEN，jsdom）

- Slot 注册表契约：注册/装配/重复注册报错。
- ui-conversation：会话列表（新建/resume/切换）、composer、流式消息（分片追加）。
- ui-tool：M3 的 tool 调用/结果对渲染成卡片（调用显示 input、结果显示 output）。
- client-shell：按 Slot 装配成单页。

### 5. `apps/web` + `packages/bundle-web`（RED→GREEN）

- Vite entry 壳（只注入，非独立应用）+ web profile 组合：host 插件 + 全量 UI 插件按序叠加。
- 构建冒烟测试（vite build 成功 + 产物含入口）。

### 6. 端到端（RED→GREEN）

- 真 host + 脚本化 WS 客户端：list → create → send（假 LLM 台词本含工具往返）→ 断言收到
  user/assistant/tool/assistant(stream 分片) 事件序列与 tool 卡片数据；重连后 resume 历史完整。

### 7. demo + 教程

- `pnpm demo:web`：零 key 起真服务 + 页面（假 LLM 台词本：一次工具往返 + 流式最终回答）。
- 教程 `docs/tutorials/M4-web.md` + 索引 + 小白验收。

## 教程交付（requirements §5.1）

`docs/tutorials/M4-web.md`：

- **动机**：M0–M3 的成果只在 `console.log` 里可见；Web 让"轨迹原料"端到端流动起来；
  为什么 client 只是"日志的又一个消费者"
- **design**：host↔client 桥时序图（plantUML：composer 发消息 → RPC → loop → 事件回推 →
  流式分片 → tool 卡片）、Client Slot 类图、流式分片时序
- **新概念**：RPC 桥、WebSocket、SSE 与流式、Slot 注册点、requestId 配对、Vite entry 壳
- **tradeoff**：为什么 WS 是唯一实时通道；为什么桥是 seam（UI 测试零网络）；为什么流式
  分片也走事件（日志真源的延伸）；为什么 apps/web 只是壳
- **动手练习**（零 key）：起 demo 在浏览器点一遍；改假 LLM 的分片台词看打字机效果；
  加一个 Slot 注册的小 UI 插件；进阶：脚本化客户端断言事件序列
- 更新 `docs/tutorials/README.md` 索引
