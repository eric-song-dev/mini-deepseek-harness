## 已核实的上游事实（定稿时直接引用，不必重查）

- **`.claude/skills -> ../.agents/skills` 是符号链接**（Claude Code 兼容别名）——同一批技能两个路径暴露，发现只扫 `.agents/skills` 一个物理根。mini 可只做 `.agents/skills`（现有根），符号链接别名留作教学注释。
- **SKILL.md 形态**：目录 bundle `<name>/SKILL.md`（可含 `references/` 等子资源）+ 平铺 `<name>.md` 双形态；不支持递归 `**/SKILL.md`。
- **frontmatter 字段**：`name`（kebab，须与目录/文件名匹配）+ `description`（目录只展示它）必填；`whenToUse`/`metadata` 可选；`disable-model-invocation`（默认 false）/`user-invocable`（默认 true）调用控制；**无 version/params**；布尔接受 YAML bool + `yes/no/on/off` + `1/0`；驼峰 legacy 键显式抛错（fail-closed）。
- **发现根按 rank**（上游多根，mini 只保留 `.agents/skills` 单根）：`project-dsh` 100（`.dsh/skills`）/ `project-agents` 200（`.agents/skills`）/ `custom` 300 / `user-dsh` 400（`~/.dsh/skills`）/ `user-agents` 500（`~/.agents/skills`）/ `bundled` 600；运行时 `register()` 用 rank 250（可被项目覆盖）；`description` 目录展示截断 500 字符。
- 上游 11 个技能实际只用 `name`+`description`（`translate-docs` 另带调用控制）——mini 最低限度只需这两个字段。
- mini 现状缺陷（M7 动机之一）：`fs-discovery` 不解析 frontmatter，`tdd` 的 frontmatter 被忽略、content 含 frontmatter 全文；无 description 则目录无法路由。

## 迷你 seam 草案（定稿时写进契约测试）

```ts
// packages/skill/src/skills.ts
interface Skill {
  name: string            // kebab-case，与目录名一致（fs-discovery 校验）
  description: string     // frontmatter 必填；目录/列表只展示它
  content: string         // frontmatter 之后的正文（frontmatter 已剥离）
  whenToUse?: string      // 可选元数据
  modelInvocable?: boolean // disable-model-invocation 的反向规范化，默认 true
  userInvocable?: boolean  // 默认 true
}

// fs-discovery：解析 YAML frontmatter（--- 块）、校验 name 与目录名一致、
// 剥离 frontmatter；坏 frontmatter fail-closed（整个 skill 报错/忽略，契约定夺）
```

YAML 解析可用轻量依赖（如 `yaml` 包）或手写最小解析（教学取舍定稿时拍板）。
