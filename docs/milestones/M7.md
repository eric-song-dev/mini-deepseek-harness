## 目标

1. **落地原版 SKILL.md 格式约定**：frontmatter 解析（`name` kebab-case +
   `description` 必填；可选 `whenToUse`、`disable-model-invocation`、`user-invocable`；
   fail-closed 校验）→ `Skill` 增 `description`、content 只返回 frontmatter 之后的正文、
   `name` 与目录名校验一致（现有 `tdd` 技能文件不动，解析器升级即兼容）。
2. **移植 6 个上游技能为 mini 版**（第一梯队 4 + 第二梯队 2，见"移植清单"）：
   去掉上游专有引用、去 `dsh-` 前缀、全中文重写，落 `<mini>/.agents/skills/` 与 `tdd`
   并列；带 references 附件的技能连同附件一起搬。
3. **skill 工具目录展示**：`list` 返回 `{ name, description }`（description 规范化 +
   500 截断，只列 modelInvocable 技能）；`get` 校验后返回含 description 的全文。
4. **验收闭环**：`skill` 工具可列出并加载全部 7 个技能（description 正确显示）；
   移植技能在本仓库真实可用（`code-review` 可对 mini 的 diff 自查）；零 key 可 demo。

**验收**：mini 的 `.agents/skills/` 下 tdd + 6 个移植技能可被 `skill` 工具
list/get（list 只含 modelInvocable、description 截断 500、get 的 content 不含
frontmatter）；frontmatter 解析契约测试全绿（坏 frontmatter/name 不匹配/驼峰
legacy 键/非布尔调用值全部 fail-closed）；移植技能在真实会话中可被假 LLM 台词按
description 路由调用；注册可逆（M6）不回归；全量测试 + typecheck 绿；demo
零 key 可跑；教程 `M7-upstream-skills` 交付并通过小白验收。

## 关键设计决策（预拍板，已与上游核对）

1. **YAML 解析用 `yaml` 包**（上游同款）。手写子集解析器在布尔宽松语义
   （`yes/no/on/off/1/0`）上有风险，教学价值不如 seam 本身。新增依赖
   `packages/skill` → `yaml`。
2. **坏条目 fail-closed + 响亮**：`discoverSkills` 遇到坏 frontmatter / 缺
   name 或 description / name 非 kebab / name 与目录名不符 / 驼峰 legacy 键 /
   非布尔调用值 → **抛 `InvalidSkillError`**（消息含文件路径与原因），整个发现
   中止。这是对上游"警告 + 跳过"的**有意偏离**：上游是多 provider 生产环境
   （一个坏技能不该杀死 agent），mini 是单根开发者自管仓库——坏 skill 与坏
   profile 一样是配置错误，M5 已有先例（"路径是文件 → 报错"）。教程 tradeoff
   一节解释。
3. **`name` 与目录名校验在发现期做**：`frontmatter.name === 目录名`，不符即
   InvalidSkillError。上游只在加载期按请求名校验（`loaded skill has invalid
   name`），mini 更严更简单——发现期就只有一个可寻址名字。
4. **`Skill` 契约扩展**：`description: string`（必填）+ 可选
   `whenToUse?: string`、`modelInvocable?: boolean`、`userInvocable?: boolean`
   （register 规范化默认 true，`get` 恒返回两个布尔）。不引入 `metadata`
   （frontmatter 该键忽略）。`createSkillsRegistry.register` 增校验（kebab
   name、非空 description、whenToUse 字符串、调用布尔），重名仍抛错（M5）。
5. **消费方边界纪律**（上游"get 是受信原语"）：过滤放 `tool.ts`——
   `list` 只含 `modelInvocable` 技能；`get` 先 kebab 校验、再查表、再
   `modelInvocable` 过滤（false → `{ error }` 结果，沿用 M5"异常是结果"语义）。
   `SkillsService.get` 保持受信不过滤。
6. **description 截断 500 在消费方**：`tool.list` 先规范化（`\s+` → 空格 + trim）
   再 `slice(0, 497) + '...'`（上游 `catalogDescription` 同款）。
7. **不做**：上游的宿主/scope 分层注册表、rank 多根扫描、Chokidar 目录监听、
   digest 缓存、`skills/change` 失效事件、`renderSkillContent` 的
   `<skill_content>` 包装（mini 的 wire 是 JSON，M5 契约 `{name, content}`
   保持并加 description）、平铺 `<name>.md` 形态、`/name` 用户显式注入、
   slash 菜单（ui-skill）——全部照 `docs/references/upstream.md` 的裁剪结论。

## 教程主题（§5.1 六要素映射）

`M7-upstream-skills`：动机（M5 有机制没内容、frontmatter 被忽略导致目录无法
路由）→ design（SKILL.md 格式契约 + 解析管线图 + skill 工具目录）→ 新概念
（frontmatter、fail-closed、调用策略四象限、description 目录路由、fail-closed
"排除而非默认放行"）→ tradeoff（单根 vs 多根 rank、抛错 vs 警告跳过、JSON wire
vs `<skill_content>` 包装、截断 500 在消费方）→ stepbystep（frontmatter.ts →
fs-discovery.ts → tool.ts → 技能文件 → e2e）→ 练习（my-frontmatter 红绿翻转 +
my-skill 的 disable-model-invocation 实验）。
