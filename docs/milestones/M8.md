- **状态**：`draft`（占位概览；开工 session 按下方"上游必读索引"读完上游后定稿，定稿后置 `proposed`）

## 目标（概览，定稿时拆解为 TDD 任务）

1. **`subagents` seam（in-process only）**：`registerProvider / getProvider / list / start` + `subagent/*` 观察事件；一个 `spawn` 提供方实现（复用 mini 现有 agentLoop + session-manager + llm + tools）。只做 **one-shot 前台**。
2. **`tool-subagent`**：注册进 mini tools seam（`register()` 返回 unregister → `ctx.effect`，M6 纪律）；前台 await result + dispose；completed → 返回 output，否则 isError。
3. **`workflowEngine` seam（同线程）** + **`tool-workflow`**：脚本钩子只做 `agent() / parallel() / pipeline() / phase() / log()`；`agent()` 内部固定走 `spawn` 提供方；meta 校验 + 脚本 parse 先行；保留 `WorkflowError(fatal)` 语义（`parallel`/`pipeline` 对 fatal 直接 re-throw，逐项 `null` 只留给子 run 失败）。
4. **轨迹衔接**：子会话 = 独立 Session（自动落 JSONL，M1 已有）；父会话只多一条 `tool` 事件记「委派子会话 id」+ `subagent/*`/`workflow/*` 观察事件（只 emit 不落父日志）；轨迹面板可导航到子会话回放。

**验收（草案）**：父 agent（假 LLM 台词本）调用 `subagent` 工具派生一个子 agent 完成子任务并回收结果，全程入轨迹；workflow 脚本跑通 `agent/parallel/pipeline` 三钩子、fatal 错误终止脚本；子会话 JSONL 独立可回放；卸载 tool-subagent / tool-workflow 后工具消失（HMR-safety）；**agent loop 一行不改**（核心验收）。

## 已核实的上游契约要点（定稿时直接引用，不必重查）

- **`SubagentRun.result` 失败不 reject**：子级失败以非 completed 的 `stopReason`（`completed|aborted|error|max-tokens|refusal`，可合并扩展）resolve；只有无法表示的基础设施故障才 reject。非 completed → 消费方映射为 isError 工具结果。
- **`subagent/start` / `subagent/end` 是 scope-filtered**：carrier 键为委派父级，父级作用域监听器只看到自己的委派；另有 `subagent/provider-added` / `provider-removed`。
- **spawn 不传 seed**（空对话开始，继承 cwd/谱系/模型）；**fork 以父 agent 已完成轮次的平衡前缀为 seed**（截至最后 `turn/end`、seq 从 0 连续），一次性快照——KV Cache 复用依赖前缀逐字节相同，故 fork 固定 one-shot。两者共用 `startInProcessRun(request, {seed?})` 五步驱动器。
- **子 agent 获得全新扁平作用域**（不继承父的工具限制/权限）；**父会话污染最小**——一次运行绝不写父会话（父只通过工具结果看到 output）。
- **workflow 是 subagent 之上的消费方**：脚本每次 `agent()` = 一次 `ctx.subagents.start()`；上游 `tool-ralph`（固定策略消费方）证明"同一引擎 + subagents"可承载专用编排策略而不改 agent loop——这正是 mini 该学的分层。
- **workflow 事件**：payload 以 `WorkflowRunInfo(id+meta)` 开头；`workflow/end` 刻意省略 result value；`agent-start/end` 按 `agent.seq` 配对。
- **失败纪律**：`parallel()`/`pipeline()` 对 fatal 错误直接 re-throw（拼错选项必须终止脚本）；逐项 `null` 只留给"子 run 失败 + 阶段内普通脚本错误"。

## 裁剪决定（草案，定稿时逐条核对）

**做（教学最小集合）**：见目标 1–4。子会话深度简化为「子会话 meta 记 `parentSessionId` + `depth`」一行字段（不照搬 delegationDepth 全机制）；`fork` 是否进 M8 由定稿 session 拍板（spawn 必做；fork 复用父日志平衡前缀，教学价值高但可后置）。

**砍掉（mini 无对应场景/过于产品化）**：

- 进程外协议全家：`subagent-acp` / `subagent-codex` / `subagent-claude-code` / `subagent-dsh-sdk`
- worker-thread 隔离（mini 同线程 `async Function` 执行脚本；注释注明"同线程 ≠ 沙箱"）
- 可继续后台 subagent 全家：`startContinuable / followup / interrupt / reportFrom / registerContinuableSetup / drainContinuableDescendants / listChildren / listDescendants`、Activation / inbox / 冷恢复 / 结算通知 / `subagent/descriptor` 投影目录（留 backlog）
- 能力矩阵与委派策略：`outputSchema / depthLimit / toolFilter / persona`、`UNSUPPORTED_CAPABILITY`、sandbox/approval 钉定
- UI 全量：`ui-subagent` 目录树与 `@` 引用、`ui-workflow-run` 独立 Chat 节点（退化为 tool 卡片显示子会话 id + 轨迹面板导航）
- `tool-subagent-control` / `tool-subagent-report`（父↔子消息通道，依赖可继续子 agent；留 backlog）

## 迷你 seam 草案（定稿时写进契约测试）

```ts
// 新包 packages/subagent：ctx.subagents
interface SubagentService {
  registerProvider(p: SubagentProvider): Unregister   // 名注册，effect 可逆（M6）
  getProvider(name): SubagentProvider
  list(): string[]
  start(name, { prompt: string, parent: Agent, signal? }): Promise<SubagentRun>
}
interface SubagentRun {
  id: string            // == 子会话 id
  result: Promise<{ output: string; stopReason: 'completed'|'aborted'|'error' }>
  dispose(): void
}
// 事件（cordis Events 模块增强，同 session/events.ts 模式，只观察不落父日志）：
'subagent/start' | 'subagent/end' | 'subagent/provider-added' | 'subagent/provider-removed'

// 新包 packages/workflow：ctx.workflowEngine
interface WorkflowEngine {
  start({ script, meta: {name, description}, args?, parent, signal? }): WorkflowRun
}
interface WorkflowRun {
  id: string; meta: { name: string; description: string }
  result: Promise<{ value; stopReason: 'completed'|'cancelled'|'error'; error?; agentsStarted: number }>
  cancel(reason?): void; dispose(): void
}
// 事件：'workflow/start' | 'workflow/phase' | 'workflow/log' |
//       'workflow/agent-start' ↔ 'workflow/agent-end' | 'workflow/end'（end 刻意省略 result value）
```

挂接方式（全零侵入 loop）：子会话 = `session-manager.create()`；子会话 ctx 继承根 ctx 的
`llm`/`tools`（M0 cordis 继承链），provider 内部对子会话 `ctx.plugin(agentLoop)`（M2 路径），
prompt 作为 user 消息跑一轮；`tool-subagent`/`tool-workflow` 走 `ctx.tools.register` + `ctx.effect`。
