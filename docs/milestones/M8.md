# M8 —— subagent / workflow（多智能体编排最小集）

- **状态**：`implemented`（2026-08-16 实现并通过验收；决策归档与实施核对见
  `implemented/architecture/2026-08-16-m8-子代理-与-workflow-决策.md`；上游调研全过程见
  `implemented/architecture/2026-08-16-m8-上游调研.md`）
- **前置**：M0–M7（已完成）。直接依赖：M1（Session 桥接 + JSONL 持久化）、M2（agentLoop）、
  M3（Tools seam）、M6（注册可逆）。
- **定位**：原 backlog #5"subagent / workflow"。让父 agent 把工作委派给子 agent
  （subagent），并让模型编写"会启动 subagent 的编排脚本"（workflow）。全部为可选能力
  插件——agent loop 不新增任何专属逻辑。

## 目标

1. **`subagents` seam（in-process only）**：`registerProvider / getProvider / list /
   start(name, request)` + `subagent/*` 观察事件；`spawn` 与 `fork` 两个提供方
   （复用 mini 现有 agentLoop + session-manager + llm + tools）。只做 one-shot 前台。
2. **`tool-subagent`**：注册进 mini tools seam（`register()` 返回 unregister →
   `ctx.effect`，M6 纪律）；跟随 provider 生命周期挂/摘；前台 await result + 总是
   dispose；completed → `{ kind:'foreground', runId, output }`，否则 isError（保留部分输出）。
3. **`workflowEngine` seam（同线程）** + **`tool-workflow`**：脚本钩子只做
   `agent() / parallel() / pipeline() / phase() / log()`；`agent()` 内部固定走
   `spawn`/`fork` 提供方；meta 校验 + 脚本 parse 先行；保留 `WorkflowError(fatal)`
   语义（`parallel`/`pipeline` 对 fatal 直接 re-throw，逐项 `null` 只留给子 run 失败）。
4. **轨迹衔接**：子会话 = 独立 Session（JSONL 自动落盘 + 谱系 meta），父会话只多一条
   `tool` 事件记「委派子会话 id」+ `subagent/*`/`workflow/*` 观察事件（emit 在父会话
   ctx，只观察不落父日志）；子会话经现有会话列表可回放（bundle-web 零改动）。

**验收（核心）**：父 agent（假 LLM 台词本）调用 `subagent` 工具派生子 agent 完成子任务
并回收结果，全程入轨迹（父 tool 事件含子会话 id；子会话 JSONL 独立可回放）；workflow
脚本跑通 agent/parallel/pipeline 三钩子、fatal 错误终止脚本、`workflow/end` 不含 value；
卸载 tool-subagent / tool-workflow 后工具消失（HMR-safety），卸载 spawn/fork 提供方后
start 抛 NO_PROVIDER；**loop 无任何 subagent/workflow 专属逻辑（仅 ToolContext 透传一行，
见决策 2）**；全量测试 + typecheck 绿；demo 零 key 可跑；教程交付并通过小白验收。

## 关键设计决策（定稿拍板，上游核对见调研 note）

1. **fork 纳入 M8**：spawn 必做、fork 一起做（~30 行增量）。`inheritsParentContext`
   （spawn=false / fork=true）只描述"子 agent 看不看父已完成轮次"；fork 的 seed =
   父日志截至最后一个 `turn/end` 的连续前缀（无已完成轮次时为空 ≈ spawn）。seed 经
   `create({ seed })` 持久化：JSONL 头记录占 seq 1，种子 seq 平移 +1（`SessionManager`
   负责重编号），resume 重放同前缀——假 LLM 可断言"子 agent 第一次模型调用看到的
   messages 含父历史"（fork 教学点的可观测性）。
2. **mini 的 `parent` 就是父会话 ctx**（对 draft 的修订）：mini 没有上游 Agent 服务，
   loop 是唯一知道"当前会话"的组件。`ToolContext` 增可选 `agent?: Context`（tools 包
   类型演进，无行为变化），loop 把会话 ctx 透传 `{ cwd, agent: ctx }`（**一行**）。
   provider 从 parent ctx 读 `session-log`（fork 种子）/ `session-meta`（谱系/cwd/
   depth）；观察事件 emit 在 parent ctx（隔离总线，天然按父级作用域过滤）。上游同款
   理由：loop 为每次模型驱动的工具调用设置 exec.agent。**draft 的"agent loop 一行不改"
   修订为"loop 无任何 subagent/workflow 专属逻辑，仅 ToolContext 透传一行"**。
3. **stopReason 词汇**：`'completed' | 'aborted' | 'error'`。映射：子 turn/end
   done→completed；limit/crash→error。aborted 仅来自启动前 signal 中止——mini loop 无
   中途取消（已知限制，代码注释注明；worker-thread 隔离是上游的解决路径，mini 不照搬）。
4. **子会话谱系**：`SessionMeta`/`CreateSessionInput` 增可选 `parentSessionId` + `depth`
   （父 depth 缺省 = 0，子 = +1；旧会话缺省 = 顶层）。**深度只记账不设限**（上游
   depthLimit 属能力矩阵，砍）；`maxSteps` 仍限制单轮工具步数。
5. **观察事件 emit 位置**：`subagent/start` / `subagent/end`（成对，同 runId+provider+
   childId；end 带 stopReason + 最后 assistant 输出）与全部 `workflow/*` 事件 emit 在
   **父会话 ctx**（Session 构造器给每会话独立 EventsService，M1 已有——不落父日志、
   按父级作用域过滤）；`subagent/provider-added` / `provider-removed` 是注册表事件，
   emit 在服务 ctx（根）。`workflow/end` 刻意省略 result value（观察者不得拿调用方
   result 的可变别名）；`workflow/agent-start/end` 按 `agent.seq` 配对；监听器异常
   隔离（记日志、不传播）。
6. **workflow 引擎同线程 `async Function` 执行**：meta/args 是纯 JSON 数据（绝不通过
   对脚本文本求值获取）；`name`/`description` 非空字符串校验 + 脚本 parse 先行（坏脚本
   在任何 agent 启动前失败）；脚本 realm 只注入 `args` + 五个钩子（不注入 fs/网络/
   timer——"同线程 ≠ 沙箱"在注释与教程注明）；返回值为 JSON-serializable 校验
   （失败 → RESULT_UNSERIALIZABLE fatal）。`result` 从不 reject；`cancel()` 只在钩子
   await 点生效（同步死循环无法打断，教程 tradeoff）；`dispose()` 幂等。
7. **`WorkflowError(fatal)` 纪律**：钩子误用（坏参数、未知 agent() 选项、脚本 parse、
   meta 非法、子 start 失败、取消）抛 `fatal: true`；`parallel()`/`pipeline()` 对 fatal
   re-throw，普通错误/子失败逐项 `null`。错误码（mini 子集）：`SCRIPT_PARSE` /
   `META_INVALID` / `INVALID_ARGUMENT` / `UNSUPPORTED_OPTION` / `AGENT_START` /
   `RESULT_UNSERIALIZABLE` / `CANCELLED`。
8. **工具面向模型的措辞**：tool-subagent 的 description 按
   `provider.inheritsParentContext` 切换（spawn="独立任务、不含本对话" / fork="继承已
   完成轮次"——上游 providerWording 同款）；tool-workflow 的 description 即脚本编写
   契约全文（meta 块、五钩子语义、误用必杀、无 fs/网络/timer、前台执行）。
9. **包布局**：新 `packages/subagent/`（seam + spawn/fork 提供方 + tool-subagent）与
   `packages/workflow/`（workflowEngine + tool-workflow）；tools 包 +`agent` 类型字段；
   session 包 +谱系/seed；agent 包 loop 一行；vitest node workspace 收新包。
   **Web 接入 = demo runtime（`web-demo-shared`）挂 host 侧插件，client（bundle-web）
   零改动**：`subagent`/`workflow` 就是 tools seam 里的普通工具，tool 卡片/轨迹面板/
   会话列表都是现成 UI，子会话经会话列表点选回放（fake 台词本第一轮即委派场景）。
   > 定稿后修订（2026-08-16，用户质询）：初版这里写的是"bundle-web 不接"——那是我把
   > draft 的"砍 UI 全量"（只砍 ui-subagent 目录树/ui-workflow-run 节点）扩大解释成了
   > "整个 Web 不接"，与 draft 目标 4"轨迹面板可导航到子会话回放"和项目 Web-first
   > 定位矛盾。已接入并回归测试锁定（`packages/web/tests/web-demo-m8.test.ts`）。

## 任务拆解（按 TDD 顺序）

### 1. session 包：谱系 meta + fork 种子（RED→GREEN→REFACTOR）

- RED：manager.test.ts 新用例——`create({ parentSessionId, depth })` 落 meta；
  `create({ seed })` 后内存日志 = 头记录 + 平移种子（seq 2..N+1）、JSONL 文件同内容、
  resume 重放同前缀；旧会话（无新字段）照常。
- GREEN：`SessionMeta`/`CreateSessionInput` 增 `parentSessionId?`/`depth?`/`seed?`；
  JSONL 后端 create 透传 meta 字段并追加 seed 行；`SessionManager.create` 负责 seed
  平移（`seq + 1`）并把 `[头记录, ...seed]` 交给 openSession。
- REFACTOR：抽出 `shiftSeed` 辅助；契约测试（persistence-contract）补 seed 语义。

### 2. tools 包 + agent 包：ToolContext.agent 透传（RED→GREEN）

- RED：agent/tests 新用例——会话上装 probe 工具（execute 读 `ctx.agent`），loop 跑一轮
  后断言 probe 收到的 agent 就是会话 ctx（可读 `session-log`/`session-meta`、emit 进
  会话隔离总线）。tools 契约测试补 `ToolContext` 可带 agent 的结构。
- GREEN：`ToolContext` 增 `agent?: Context`（类型演进）；loop 的 tools.execute 调用
  改 `{ cwd, agent: ctx }`（一行透传，无其他逻辑改动）。
- REFACTOR：注释说明"loop 是唯一知道当前会话的组件"。

### 3. subagents seam：注册表 + 事件（RED→GREEN→REFACTOR）

- RED：`packages/subagent/tests/` 契约测试 `subagents-contract.ts`——register/get/list
  保序、重名报错、幂等撤销（撤销后 get/list 不可见、start 抛 NO_PROVIDER、同名可重注

  provider 抛 `SubagentError('NO_PROVIDER')`；HMR-safety：dispose 提供方插件 fiber →
  provider 消失 + provider-removed 发出。
- GREEN：`service.ts`——`SubagentRuntime`（cordis Service，inject `['session-manager']`）
  + `SubagentError` + 事件词汇模块增强；`provideSubagents` 注入插件。
- REFACTOR：词汇类型（SubagentRunInfo/EndInfo/Provider/StartRequest/Run/Result）集中
  `types.ts`。

### 4. spawn / fork 提供方（RED→GREEN→REFACTOR）

- RED：provider 测试——spawn：start 建子会话（meta.parentSessionId=父 id、depth=父+1、
  cwd 继承）、子会话装 agentLoop 跑一轮（假 LLM 台词）、run.id == 子会话 id、result
  output == 最后非空 assistant 文本、父日志零污染、子日志完整（turn 全事件）；子模型
  crash → stopReason 'error'；signal 已中止 → start reject 且无事件对；事件对
  subagent/start/end（payload 全字段）emit 在父会话 ctx 且不进父日志。fork：seed =
  父已完成轮次前缀（子模型第一次调用 messages 含父历史、当前轮不完整时不含进行中
  轮）、无已完成轮次时等价 spawn。dispose 幂等。
- GREEN：`providers.ts`——`startInProcessRun(request, { seed? })` 五步驱动器 mini 版
  （校验 → session-manager.create（带谱系/seed）→ child.ctx.plugin(agentLoop) →
  loop.chat(prompt) → 读结果 + dispose 子会话）；`spawnProvider` / `forkProvider`
  插件（config：providerName/systemPrompt/maxSteps/stream），注册返回 unregister +
  `ctx.effect`。
- REFACTOR：`completedTurnPrefix` 抽公共；输出选取（最后非空 assistant）抽函数。

### 5. tool-subagent（RED→GREEN→REFACTOR）

- RED：工具测试——provider 在时挂 `subagent` 工具（description 按 inheritsParentContext
  切换）、provider 不在时不挂、provider-removed 时摘（HMR-safety：dispose 工具插件
  fiber → 工具消失）；execute：前台收集（completed → `{kind:'foreground', runId,
  output}`、run 已 dispose 即子会话已落盘排空）、非 completed → 抛错带部分输出；
  无 agent 上下文（程序直接调 execute）→ 抛错；父日志只有 tool 调用/结果事件。
- GREEN：`tool.ts`——`createSubagentTool` + `toolSubagent` 插件（inject
  `['tools','subagents']`，config：provider 默认 'spawn'、toolName 默认 'subagent'）。
- REFACTOR：措辞函数 `providerWording`；stopReason→错误消息映射（completed 唯一成功）。

### 6. workflowEngine seam（RED→GREEN→REFACTOR）

- RED：`packages/workflow/tests/` 契约/引擎测试——meta 非法（缺 name/description/坏
  phases）→ start 同步抛 META_INVALID；坏脚本 → SCRIPT_PARSE（parse 先行，无任何
  agent 启动）；agent() 走 ctx.subagents（spawn 默认，config 可换 fork）：completed →
  返回 output 文本、非 completed → 返回 null、start 失败 → fatal AGENT_START；
  parallel：thunk 抛普通错 → 该元素 null、fatal → 整体 reject；pipeline：无跨阶段
  屏障（item 独立推进）、阶段普通错 → 该 item null 且跳过剩余阶段；未知 agent() 选项
  → UNSUPPORTED_OPTION fatal；脚本返回值 JSON-serializable 校验；result 从不 reject
  （completed/cancelled/error + error 消息 + agentsStarted）；cancel → cancelled
  （脚本后到返回不覆盖）；事件全序列（start/phase/log/agent-start↔agent-end/end，
  end 无 value、agent 按 seq 配对）emit 在父会话 ctx；监听器抛错不炸脚本；dispose
  幂等。
- GREEN：`engine.ts`——`WorkflowEngine`（cordis Service，inject `['subagents']`，
  config：provider/maxTotalAgents? 砍——不做上限）+ `WorkflowError` + 同线程
  AsyncFunction 执行 + 事件容器化 emit。
- REFACTOR：钩子工厂抽公共（seq 计数、label 兜底 prompt 前 20 字符）。

### 7. tool-workflow（RED→GREEN→REFACTOR）

- RED：工具测试——挂 `workflow` 工具（description 即脚本契约全文）；execute：completed
  → `{ runId, agentsStarted, result }`；cancelled/error → isError 消息；无 agent 上下文
  → 抛错；总是 dispose（run 停稳后工具才返回）；HMR-safety：dispose 插件 fiber →
  工具消失。
- GREEN：`tool.ts`——`toolWorkflow` 插件（inject `['tools','workflowEngine']`，
  config：toolName 默认 'workflow'、maxResultChars 默认 50000）；结果渲染
  `workflow "<name>" completed (N agents). Return value: <json>`（超长截断）。
- REFACTOR：stopReason→错误消息映射与 tool-subagent 保持同款结构。

## 教程主题（§5.1 六要素）

`M8-subagent-workflow`：多智能体——子代理怎么派生（spawn/fork 的 seed 差异）、结果怎么
回收（result 不 reject + 前台收集 + dispose）、workflow 脚本钩子怎么编排
（agent/parallel/pipeline + fatal 纪律）。新概念：provider 注册表（多实现 seam vs 单
实现 seam）、委派与谱系（parentSessionId/depth）、fork 平衡前缀、fatal 错误纪律、
同线程脚本执行（≠ 沙箱）。tradeoff：为什么不改 loop、为什么子会话独立落 JSONL、
为什么 result 不 reject、为什么 workflow 只做脚本协调、为什么没有中途取消。
练习：`my-subagent.test.ts` + `my-workflow.test.ts`。
