# M9 —— MCP（外部工具协议接入）

- **状态**：`implemented`（2026-08-16 完成；上游调研见 `.agents/notes/implemented/architecture/2026-08-16-m9-上游调研.md`，决策归档见同目录 `2026-08-16-m9-mcp-决策.md`）
- **前置**：M0–M8（排期中）。直接依赖：M3（Tools seam + 执行管线）、M6（注册可逆）。
- **定位**：原 backlog #6"MCP、LSP"的 MCP 部分；**LSP 继续留在 backlog**。让外部 MCP
  server 提供的工具成为 mini Tools 注册表里的普通工具——`agent loop` 一行不改。

## 目标

1. **mcp-client seam**：连接 MCP server（**只做 stdio transport**）、分页发现 `listTools`、
   把每个工具以 `mcp__<serverName>__<rawName>` 命名注册进现有 Tools 注册表
   （复用官方 `@modelcontextprotocol/sdk` 的 `Client` + `StdioClientTransport`，不手写协议）。
2. **配置与生命周期**：server 配置 = profile.yml 插件行 `options`（opt-in，无 preset 默认
   实例）；**两阶段同步**（fetch 新代 → swap，fetch 失败保留旧代、register 冲突回滚整代）；
   连接断开即撤销全部该 server 的工具注册（M6 纪律），dispose 后重新 apply 可重连重注册
   （HMR-safety 测试）。
3. **执行语义**：MCP 工具走现有执行管线，无专用 MCP 工具类型——模型与 Trajectory 对 MCP
   工具和本地工具一视同仁；`isError` 是结果不是异常（mini 纪律），transport 级失败才 throw。
4. **零 key demo**：仓库内自带玩具 stdio MCP server（真协议真进程），假 LLM 台词本调用其
   工具，全程入轨迹；e2e 再连官方 `@modelcontextprotocol/server-filesystem` 证明互操作。
5. **Web 可见路径（M8 教训）**：demo:web 的共享 runtime 挂一个 mcpClient 实例，浏览器里
   MCP 工具卡片与本地工具同形态可见（不做 MCP 配置 UI）。

## 包与 seam 契约

新包 `packages/mcp`（`@mini-dsh/mcp`），namespace 插件（上游同款：具名导出
name/inject/apply，无 default export），**不造独立服务键**：

```ts
export const name = 'mcp-client'
export const inject = ['tools']           // 唯一依赖：现有 Tools 注册表
export interface McpConfig {
  serverName: string        // ^[A-Za-z0-9_-]{1,32}，必填，跨存活实例唯一
  transport: 'stdio'        // mini 只做 stdio；校验拒绝其他值
  command: string           // 必填，如 'npx'、'node'
  args?: string[]           // 默认 []
  env?: Record<string, string>  // 默认 {}，覆盖在 {...process.env} 上（不 scrub——裁剪）
  cwd?: string              // 默认 process.cwd()
}
export async function apply(ctx: Context, rawConfig: unknown): Promise<void>
```

- **配置落点（拍板）**：profile.yml 插件行的 `options`——kernel 零改动；
  环境变量不是配置落点，只是 `env` 字段的数据源。
- **模块拆解**：`config.ts`（手写 resolveConfig 校验 + 默认值，错误带字段名）、
  `tools.ts`（`publicToolName` / `syncTools` 两阶段 / executor / 结果映射 /
  `McpClientLike` 窄接口——单测用 fake client，真实现是 SDK Client）、
  `index.ts`（插件 apply：校验 → serverName 预留（WeakMap 按 ctx.root）→
  connect → 初始同步（失败恒 throw = 插件启动失败）→ onclose 断开即撤销 →
  list_changed 重同步 → ctx.effect 挂 dispose：关连接 + 注销全部 + 释放 serverName）。

## 关键语义（定稿）

1. **命名**：`publicToolName(serverName, rawName)` =
   `mcp__${serverName}__${rawName}`，非法字符 `[^A-Za-z0-9_-]` → `_`；
   **超长（>64）报错**（不截断不 hash——裁剪决定：mini 注册表重名必抛、同步冲突整代
   回滚，规范化碰撞绝不静默损坏；hash 分支是产品级细节）。rawName 只走 wire，
   公开名绝不发服务器、绝不解析还原。
2. **两阶段同步**：fetch（分页攒齐新一代定义；网络错/重复列名/超长名 → reject，
   **不碰注册表**）→ swap（先 dispose 旧代全部，再逐个 register；register 冲突 →
   回滚已注册的新代再抛错）。调用方：初始同步 = apply 抛出（插件启动失败）；
   重同步（list_changed）= catch 后保留旧代 + error 日志。
3. **执行语义**：executor 闭包持有 (client, rawName)，`client.callTool({ name: rawName,
   arguments: input })`；input 非对象 → 兜底 `{}`；结果映射：text 块 `\n` 连接，
   image/audio/resource/未知块 → 占位符（上游同款文案）；`isError:true` → 返回
   `{ isError: true, content: text }` 结果对象（**不 throw**，模型可见可纠正）；
   正常返回 `{ content: text }`；仅 transport 级失败 throw（→ loop crash 路径）。
   不做 signal 取消、不做 toolCallTimeoutMs（SDK 默认 60s 兜底）。
4. **断开即撤销**：`client.onclose`（stdio 子进程退出触发）→ 全部 disposer off() +
   Map 清空 + warn 日志；已断开后的调用自然失败。重连 = dispose 后重新 apply 同
   config（公开名是纯函数，重建完全相同的名字）。
5. **serverName 预留**：`WeakMap<Context, Set<string>>` 按 ctx.root 键控，ctx.effect
   挂载/释放；重复 serverName → 后加载实例启动失败，前实例无损。
