## 已核实的上游事实（定稿时直接引用，不必重查）

- **架构本质**：MCP 只是"工具生产者"——插件 `inject: ['tools']`，连接后 `listTools` 分页发现，逐个以原始 `ToolDefinition` 注册进现有 `ctx.tools`，之后自动流入现有执行管线；**无专用 MCP 工具类型**。
- **命名**：公开名 `mcp__<serverName>__<rawName>`（`rawName` 只走 wire，公开名绝不发服务器），是 `(serverName, rawName)` 的纯函数；规范化：≤64 字符、`[A-Za-z0-9_-]`，替换/截断改变名字时追加 `sha256(serverName\0rawName)` 前 12 位 hex（`tools.ts` 的 `publicToolName()`）；`serverName` 满足 `^[A-Za-z0-9_-]{1,32}` 且跨存活实例唯一。
- **插件实例形态**：一个插件实例 = 一个 MCP server（namespace 插件 `name='mcp-client'`、`inject=['tools']`）；N 个 server 在 cordis.yml 里加载 N 个同名不同 config 的实例；Config 是 transport 判别的扁平联合（stdio：`serverName/command(必)/args?/env?/cwd?/toolCallTimeoutMs?/failOnStartupError?`），公共默认 `toolCallTimeoutMs=60000`。
- **SDK**：`@modelcontextprotocol/sdk ^1.12.0`（唯一 MCP 依赖；官方测试/演示 server 包：`@modelcontextprotocol/server-everything`、`server-filesystem`）；transport 支持 stdio + streamable-http（mini 只做 stdio）。
- **执行语义**：MCP 插件**不订阅任何 tools/* 事件**——注册后自动被现有管线包裹（pre-execute/execute/post-execute/result/change）；`exec.signal` 透传给 SDK `callTool`（→ `$/cancelRequest`）；结果映射：text 块 `\n` 连接、image/audio/resource → 占位符、`isError:true` → throw → ToolRuntime 错误路径。
- **配置/生命周期**：纯 opt-in（无 preset 默认实例；真实组合示例见 `examples/mcp-memory/*.cordis.yml`）；两阶段同步（fetch→swap，失败保留旧代、冲突回滚整代）；重连监督器为有界指数退避（initialDelayMs=500 翻倍、maxDelayMs=30000、maxAttempts=10，预算耗尽注销工具停止重连——**mini 用 `reconnect.enabled:false` 的简单语义**）；可逆 dispose（关连接 + 注销工具 + 取消 timer）。

## 裁剪决定（草案，定稿时逐条核对）

**做**：stdio transport + 一个真 server demo + 官方 SDK `Client`/`StdioClientTransport` + 注册进现有注册表 + 两阶段同步 + 可逆 dispose。

**砍掉**：

- streamable-http transport（stdio 足以教学；多 transport 是产品矩阵）
- 自动重连监督器（约 351 行；mini 用"断开即撤销 + 手动/配置重连"的简单语义）
- OAuth / 鉴权流、headers 透传、resources / prompts 能力面（只做 tools）
- outputSchema 校验 + structuredContent（只保留 content 文本投影）、公开名 hash 规范化（sha256 后缀）分支——简化为前缀 + 非法字符替换 + 超长报错、invariants 伴生、`failOnStartupError` 二态（初始失败直接 throw）、stdio env 清洗 `scrubbedParentEnv`（清 `/KEY|PASSWORD|SECRET|TOKEN/i` 与 `DSH_*`）——简化为 `{...process.env, ...config.env}` 或留 TODO
- MCP 配置 UI（Web 里只读展示 server 状态即可，配置在 profile/环境变量）

## 迷你 seam 草案（定稿时写进契约测试）

```ts
// 新包 packages/mcp：沿用上游形态——namespace 插件，不造独立服务键
// 一个插件实例 = 一个 MCP server；N 个 server = cordis.yml 里 N 个同名不同 config 的实例
export const name = 'mcp-client'           // 插件名
export const inject = ['tools']            // 唯一依赖：现有 Tools 注册表
interface Config {
  serverName: string        // ^[A-Za-z0-9_-]{1,32}，跨实例唯一；命名空间（工具名 mcp__<name>__<raw>）
  transport: 'stdio'        // mini 只做 stdio
  command: string           // 如 'npx'
  args?: string[]           // 如 ['-y', '@modelcontextprotocol/server-filesystem', ...]
  env?: Record<string,string>; cwd?: string
}
// apply：new Client + connect(new StdioClientTransport({command,args,env,cwd}))
//   → listTools() 分页 → 每个工具 register 进 ctx.tools（disposer 收进数组）
// 两阶段同步：fetch 新代 → swap 旧代（失败保留旧代）；断开 → 全部 off()（幂等）；
// ctx.effect 挂 dispose：关连接 + 注销全部工具 + 取消 timer（M6 可逆纪律）
```

配置落点定稿时拍板：`profile.yml` 扩展段或启动器环境变量（教学取最小）。
