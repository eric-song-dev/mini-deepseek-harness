# 里程碑 specs

每个里程碑 M 的**详细执行 spec** 放这里：`M<n>.md`，M0–M10 各有一份（M7–M10 为 `draft` 占位）。

- `docs/requirements.md` §9 是里程碑概览表（一 M 一行），只做导航。
- 本目录是当前 M 的**唯一执行依据**：任务拆解、TDD 顺序、验收、教程要求、完成后收尾动作。
- **生命周期**：`draft`（占位，只有概览 + 上游必读索引）→ `proposed`（当前 M，已定稿）→ `implemented`（完成归档）。
- **定稿时机（防过度设计）**：`M<n>.md` 由**上一个 M 收尾时的 session** 定稿（拆解任务、验收、教程），记入 notes，用户可审查；定稿后状态改为 `proposed`。不在需求阶段提前写后续 M 的细节。
- **M7–M10 开工协议（2026-08-16 新增）**：定稿 spec 之前，先按 `docs/references/upstream.md`
  里该 M 的上游源码索引读上游**文档与代码**（照搬概念不照搬代码、一次只读一个文件），
  再拆解任务。M7–M10 的 draft 文件里已给出每个 M 的上游必读清单，定稿时核对并补充。
