# M6 —— 一切注册皆可逆（注册即 effect）

- **状态**：`proposed`（2026-08-16 定稿；由用户指令启动——审计发现自有 seam 的注册不可逆）
- **前置**：M0–M5（已完成）。依赖：M1 的 Session 桥接、M3 的 Tools seam、M4 的
  RpcBridge / Slot / client store、M5 的 Skills seam。
- **依赖关系**：M0–M5 中所有由 cordis 托管的注册（`ctx.provide` / `ctx.plugin` /
  `ctx.on`）天然可逆，但**自建注册表**（Tools/Skills/RpcBridge/SlotRegistry）只有
  "注册"没有"撤销"，client 的桥订阅链（store → bridge → transport）从不退订——
  违背上游 `architecture.md` 的核心教义：**"registrations are effects that unwind
  when their plugin unloads"**。M6 把可逆性从 cordis 边界推广到自己的每个 seam，
  并补上上游 `testing.md` 的对应纪律：*Every registry gets an HMR-safety test
  (dispose the contributing fiber, assert cleanup)*。

## 目标

1. **所有自有 seam 的注册都可撤销**：`ToolsService` / `SkillsService` /
   `RpcBridge` / `SlotRegistry` 的注册 API 返回幂等撤销函数，注册方插件用
   `ctx.effect` 挂接，卸载即撤销。
2. **client 订阅链闭环**：store 的 `onEvent` 订阅、bridge 的 transport 监听器、
   WebSocket 连接在 shell 卸载时全部清理（无泄漏、无悬挂）。
3. **会话与 loop 收尾**：会话卸载时排队的落盘写完成；`agent-loop` 句柄随 fiber 摘除。
4. **HMR-safety 测试组**：每个注册表一组"dispose 注册方 fiber → 断言注册消失"的测试。

**验收：卸载任一注册插件后其注册项消失（工具 / RPC 方法 / slot / 订阅 / 句柄），
全量测试与 typecheck 绿，demo 零 key 可跑。**

## 关键设计决策（预拍板，M6 开工时逐条核对）

1. **统一模式："注册返回撤销函数"**。`register(...)` / `addHook(...)` /
   `handle(...)` 一律返回幂等的 `() => void`；注册方插件写
   `const off = seam.register(x); ctx.effect(() => () => off())`。
   撤销函数幂等（重复调用无害），撤销后行为 == 从未注册过。
   不新增 `unregister(name)` / `removeHook(phase, hook)` 之类按名查找的删除 API——
   返回函数最简单、无二义性（闭包直接持有被注册对象，天然避免"删错同名项"）。
2. **client 订阅链的归属**：`clientShell` 是装配者（M4 决策），由它用
   `ctx.effect` 负责卸载时的 `store.dispose()`（退订 `bridge.onEvent` + 清空
   store 监听器）与 `bridge.close()`（关 transport）。store 增加幂等 `dispose()`；
   `createBridgeClient` 保存 transport 的 `onMessage`/`onClose` 取消函数，
   `close()` 幂等：拒绝未决请求 → 清空事件订阅 → 摘监听器 → 关 transport。
   `wsClientBridge` 的 socket `open` 监听器在 open 后即摘（一次性）。
3. **webHost 的 RPC handler**：4 个 `bridge.handle` 全部走
   `ctx.effect(() => () => off())`——即使默认路径的桥是插件自建（随插件消亡），
   注入桥的路径（测试/HMR）也必须正确撤销。
4. **会话卸载 = 落盘排空**：Session 在 fiber dispose 时等待 `flush()` 完成
   （pendingWrites 链排空后再释放）。cordis 的 dispose 事件是否被 `fiber.dispose()`
   等待由测试实证；若不等待，改由 SessionManager 追踪已开会话并显式
   `await session.dispose()`（webHost 的 residents 关闭逻辑保持现状作为双保险）。
5. **agent-loop 句柄**：`Object.defineProperty(ctx, 'agent-loop', …)`（configurable
   已为 true）配 `ctx.effect(() => () => delete ctx['agent-loop'])`——注册与撤销对称，
   fiber dispose 后句柄消失。
6. **HMR-safety 测试落点**：每个注册表一组测试（tools / skill / web 桥 / client
   slot+store+connection / session / agent），全部走"真插件挂到测试 ctx →
   `fiber.dispose()` → 断言注册消失、行为回到未注册态"。契约测试
   （`tests/contracts/`）同步增补撤销语义，任何未来实现都必须遵守。
7. **不做**：不做上游完整的 HMR 热替换运行时（backlog #11 动态插件热加载的前置
   条件由本 M 备好，热加载本身仍是 backlog）；不给 cordis 提供的服务（provide/on）
   另造撤销机制（已天然可逆）；不动 `defineProperty` 的自有属性方案（session-log
   等随 ctx 消亡，无泄漏面，仅补测试说明）。

## 任务拆解（按 TDD 顺序）

  函数（撤销后 hook 不再执行）。新 `tests/reversibility.test.ts`：

  4 个工具插件改用 `ctx.effect(() => () => off())`。
- REFACTOR：撤销函数的幂等实现抽共用；注释补"注册即 effect"教学点。

### 3. web：RpcBridge 撤销 + webHost effect（RED→GREEN→REFACTOR）

### 4. client：slot 撤销 + ui 插件 effect + 订阅链闭环（RED→GREEN→REFACTOR）

- REFACTOR：4 个 ui 插件的 effect 模式抽成 `registerSlot(ctx, name, entry)` 助手

## 教程交付（requirements §5.1）

`docs/tutorials/M6-reversible-registrations.md`：

- **动机**：插件能装上也要能拆下——否则"一切皆为插件"只有半条命（上游原话
  "registrations are effects"；HMR 与热插拔的地基）
- **design**：注册返回撤销函数的模式图 + `ctx.effect` 生命周期时序（plantUML）；
  卸载工具插件前后注册表状态对照
- **新概念**：可逆注册 / 撤销函数（unregister closure）、effect 清理、HMR-safety
  测试、幂等卸载、订阅泄漏（listener leak）
- **tradeoff**：为什么返回撤销函数而不是按名 unregister；为什么 webHost 默认
  自建桥还要挂 effect（注入路径的 HMR）；为什么订阅链的清理归 shell（装配者）
  而不是 store（服务）
- **动手练习**（零 key）：①my-unload-tool——注册自定义工具 → 卸载 fiber →
  断言工具消失（先写"工具还在"的错误断言看红再翻转）；②撤销 RPC handler 后
  请求得到 UnknownMethodError；③撤销 slot 后面板不再渲染；④进阶：给一个
  setInterval 插件装 ctx.effect 清理，卸载后不再触发
- 更新 `docs/tutorials/README.md` 索引
