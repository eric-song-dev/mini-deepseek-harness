## 已核实的上游事实（9 项索引逐文件读完）

1. **`docs/subsystems/web.zh.md`（能力 seam 总纲）**：三层拆分（Service Definition
   `ctx.web` + Provider 插件组 + Consumer `tool-web`）；Web 是可选项、不属于 loop 主干；
   search/fetch 两操作有意共用一个 seam（一套选择策略、一套错误/中止词汇）。请求只带
   `query`；`maxResults` 是消费方上限，seam 在返回路径强制（截断 + `truncated`）。
   `WebSearchSource` 的 title/snippet/publishedAt 全可选（不强迫提供方编造）。
   `available()` 是廉价本地检查、禁止网络调用；选择在执行时解析、绝不依赖注册/配置/HMR
   顺序；六支选择语义 + `WebError` 码表（open code string，非封闭联合）。
2. **`packages/web/web/README.zh.md`（Service Definition）**：服务 API = register
   （重 id 抛 `WEB_DUPLICATE_PROVIDER`，返回 disposer 随 fiber dispose）/ search（解析
   提供方 + 强制 maxResults）/ fetch。配置 id 落点：配置 `searchProvider` 或环境变量
   `$DSH_WEB_SEARCH_PROVIDER`。**无观测接口**：没有提供方变更事件/能力状态查询，可用性
   只能靠执行并按 code 路由观测。提供方注册的是**能力**而非工具。
3. **`packages/web/tool-web/README.zh.md`（消费方）**：面向模型的一切（名称/schema/
   提示词段/结果上限/结果格式/呈现）唯一归属方；**绝不 import 具体提供方、绝不调用
   `available()`、绝不枚举提供方**，唯一执行路径是 `ctx.web.search()`。**稳定注册**：
   工具跟随产品启用状态而非后端可用性——provider 缺失/错误配置/歧义/不可用时工具仍在，
   执行抛结构化 WebError 由 ToolRuntime 转成模型可读错误结果。`max_results` 有意不做
   模型参数（部署设置）。`searchTimeoutMs` 默认 30000（协作式超时预算，不面向模型）。
   空 query → `Error: query must be a non-empty string`。结果格式：可选答案 → `Sources:`
   → `- [<title-or-url>](<url>) — <snippet> (<publishedAt>)` 行；无答案无来源 →
   `No results found.`；截断 → `(Showing the first <count> sources. Refine the query
   for more.)`；结尾恒有 `Cite the relevant URLs above as markdown links in your answer.`。
   仅搜索指引（无 fetch）："Use the web_search tool to discover current information on
   the web. It returns an optional answer plus a list of source URLs. Use the returned
   source snippets when available, and cite the relevant URLs as markdown links."
4. **`tool-web/src/search.ts`**：`WEB_SEARCH_MAX_RESULTS = 8`；`parseSearchArgs`（trim
   后空 → 抛 'query must be a non-empty string'）；`sourceLabel` = title ?? hostname ??
   原串；`formatSearchOutput` 精确拼装算法（snippet 与 `(publishedAt)` 合成 ` — meta`
   后缀）；工具声明（name `web_search`、description 'Search the web for current
   information. Returns an optional summary answer and a list of source URLs.'、
   parameters `{query: string}` required）；execute = parse → `ctx.web.search({query,
   maxResults}, exec.signal)` → 返回 `{content?, sources, truncated}`（投影掉缺失可选
   字段）。上游特有：output.schema/render/presentationMeta/timeoutMs/isConcurrencySafe。
5. **`web-search-deepseek/README.zh.md`**：Anthropic 兼容 Messages API（`POST
   {baseURL}/messages`，默认 `https://api.deepseek.com/anthropic/v1`，**不复用**
   `$DEEPSEEK_BASE_URL`——那是 chat-completions 基址）+ 原生 `web_search_20250305`
   服务器工具；每次搜索 = 一次完整 Messages 模型轮次；解析结构化
   `web_search_tool_result` 块（**绝不从模型文本抓 URL**）；无块 → **严格模式**抛
   `WEB_PROVIDER_ERROR` 不降级；复用 `DEEPSEEK_API_KEY` 凭据；`content` 从不信任提供方
   答案（省略）；sources ← `web_search_result` 条目（url/title/page_age→publishedAt），
   snippet ← text 块 `citations[]` 的 `cited_text`（按 URL 关联）；按 URL 去重；
   maxResults 由 seam 事后截断（协议无结果数旋钮，只有 maxUses）；失败 → `WEB_PROVIDER_ERROR`，
   取消 → `WEB_ABORTED`，重定向在接触 Location 前拒绝；配置：apiKey/apiKeyEnv
   （默认 DEEPSEEK_API_KEY）/baseURL（env `DEEPSEEK_SEARCH_BASE_URL` 兜底）/model
   （`deepseek-v4-flash`）/apiVersion（`2023-06-01`）/maxTokens（4096）/maxUses（5）。
6. **`src/{types,provider,index}.ts`**：wire 类型（WebSearchResultItem{url,title?,
   page_age?}、WebSearchToolResultBlock、CitationLocation{url?,cited_text?}、TextBlock、
   AnthropicResponse/Error）；`DEEPSEEK_PROVIDER_ID = 'deepseek-official'`；请求 body
   `{model, max_tokens, messages:[{role:'user', content:[{type:'text', text:'Perform a
   web search for the query: <query>'}]}], tools:[{type:'web_search_20250305', name:
   'web_search', max_uses}]}`；headers 同时发 `x-api-key` 与 `Authorization: Bearer` +
   `anthropic-version`；`redirect: 'error'`；错误消息文案（aborted / request failed /
   unprocessable body / no blocks / credential missing）；`citationSnippets` 首见胜；
   `mapAnthropicResponse` 过滤+去重+空字段省略，`truncated` 恒 false；`available()` =
   key 可解析 && URL.canParse(baseURL) && maxTokens/maxUses 正整数（**不检查网络**）；
   options 按次投影（settings 层语义）；插件 `inject: ['web']`，Config schema 默认值。
7. **`docs/cookbook/adding-a-tool.zh.md`**：execute 约定——参数已校验（schema DSL 表达
   不了的约束手动查）、返回规范 JSON 值（渲染是独立关注点）、抛异常/无效值 = isError、
   遵守 `exec.signal`；策略不内建到工具（pre-execute 挂接）。mini 的 M3 已实现大部分；
   差异：mini 工具无 output.schema/render 层、无 exec.signal。
8. **`docs/tool-catalog.zh.md`**：模型可见 schema = `{type:'object', properties:{query:
   {type:'string', description:'The search query.'}}, required:['query']}`。
9. **perplexity / exa README（对比，一眼即可）**：同一 seam 契约、各自 wire 与映射
   （perplexity：chat/completions + content←生成答案 + search_results/citations 双路径；
   exa：/search + 无 content + highlights→snippet + numResults 请求层优化）——证明
   "换提供方不改模型侧"。

## 裁剪逐条核对（draft 九条 → 定稿结论）

- **web_fetch 是否顺带**：**不做**。fetch 的 URL 安全策略（重定向/字节上限/私有网络）
  是独立子系统；教学焦点是 search 的选择语义与"第一个外部 HTTP 工具"。留 backlog。
- **CONFIGURED_* 两支**：**做全**。mini 的 webRuntime 有 `searchProvider` 配置 id
  （profile.yml 插件 options），六支选择语义都有意义；砍掉的只是 env 层
  （`$DSH_WEB_SEARCH_PROVIDER` 不读——配置只走插件 config，文档注明）。
- **WebError 码表**：`WEB_PROVIDER_UNAVAILABLE` / `WEB_PROVIDER_CONFIGURED_MISSING` /
  `WEB_PROVIDER_CONFIGURED_UNAVAILABLE` / `WEB_PROVIDER_AMBIGUOUS` /
  `WEB_DUPLICATE_PROVIDER` / `WEB_ABORTED` / `WEB_PROVIDER_ERROR` /
  `WEB_PROVIDER_CREDENTIAL_MISSING`（8 个；最后一个非 draft 清单，是 deepseek 提供方
  需要——上游同码，错误消息指引"存 key 到环境变量"）。
- **凭据**：直接读 `process.env`（`DEEPSEEK_API_KEY`，apiKeyEnv 可换）；无 credentials
  seam。每次 search 现读（无 settings 层可换，注册时快照已足够——mini 配置静态）。
- **结果格式（模型可见）**：mini 工具管线无 output.render 层——工具返回**结构化归一化
  结果** `{content?, sources, truncated}`（轨迹面板直接展示 result JSON；模型经
  JSON.stringify 看到同结构，URL 仍可引用）。上游的 Sources: markdown 渲染与
  `presentationMeta` UI 卡片同步砍。cite 指引（上游系统提示词段）并进工具 description
  ——mini 无 system-prompt seam。
- **searchTimeoutMs（默认 30000）**：做，但落点不同——上游是 timeout-policy 包装层
  （mini 没有）；mini 在 webSearchTool execute 内自建 AbortController + setTimeout，
  signal 透传给 `ctx.web.search()`（seam 的 signal 参数保留——契约完整）。Mini 的
  ToolContext 不加 signal 字段（不扩 M3 契约）。
- **配置落点**：profile.yml 插件 options——webRuntime `{searchProvider?}`、
  webSearchTool `{searchMaxResults?, searchTimeoutMs?}`、deepseekWebSearch
  `{apiKey?, apiKeyEnv?, baseURL?, model?, apiVersion?, maxTokens?, maxUses?}`。
- **砍**：web_fetch / turndown / fetch 安全策略；credentials seam；settings 层叠加；
  `web/deepseek-search-llm-request` 请求日志事件（tool 事件已记调用）；UI web 卡片；
  perplexity / exa；`$DSH_WEB_SEARCH_PROVIDER` env 层。

## mini 挂接点核对结论

- **无服务键冲突**：全仓 grep 证实无 `provide('web')`、无 `ctx.web` 使用。`ctx.web`
  服务键安全（mini 的 packages/web 提供 rpcBridge/sessionManager，不占 'web'）。
- **Tools seam**：`Tool {declaration, execute(input, ctx)}`；注册返回幂等撤销函数
  （M6）；无 output.schema/render/signal。`{error}` 结果语义有先例（skill 工具）。
- **Loop**：工具抛错 → turn/end(crash) 上抛；所以稳定注册要求 webSearchTool 自己把
  WebError 转 `{error}` 结果（skill 工具同款纪律）；loop 一行不改（M10 验收点）。
- **模型可见性**：工具输出经 `JSON.stringify` 回填 role:'tool' 消息。
- **假 HTTP 端点测试模式**：llm adapter 的 `options.fetch` 注入模式复用
  （deepseekWebSearch 加 `fetch?` 配置）。
- **profile 装载**：`loadProfile` 逐行 import + options 原样传插件 config——"profile
  加插件行即获能力"的验收路径成立。
- **demo 形态**：M9 mcp-demo 三幕骨架复用；web-demo-shared 是 Web 接入点
  （fake 台词本第三轮插入 web_search 场景）。
- **fakellm 耗尽纪律**：台词本耗尽抛 FakeLlmExhaustedError——fakeWebSearch 同款。

## 拍板（M10 spec 定稿的十项决策）

1. **单包** `packages/web-search`（`@mini-dsh/web-search`）：mini 包粒度 = 子系统粒度
   （M9 同款）；三层拆分在包内文件边界体现（`web.ts` seam / `fake.ts` / `deepseek.ts` /
   `tool.ts`），换 provider = 加一个文件 + profile 加一行。
2. **服务键** `web`（上游对齐）：`webRuntime` 插件 `ctx.provide('web', ...)`；
   `webSearchTool` `inject: ['tools', 'web']`；两个 provider 插件 `inject: ['web']`。
3. **Seam 契约**（与上游 type-equiv 同构）：WebSearchRequest/Result/Source、
   WebSearchProvider{id, available(), search(req, signal?)}、WebRuntime
   {registerSearchProvider→Unregister, search(req, signal?)}、WebError{code}。
   register 重 id 抛 WEB_DUPLICATE_PROVIDER；search 六支选择 + maxResults 强制
   （截断 + `truncated = 提供方值 || 本次截断`）。
4. **fakeWebSearch**（mini 专属）：id `'fake'`，available() 恒 true；台词本 config
   `results?: WebSearchResult[]`（按序消费，耗尽抛 FakeWebSearchExhaustedError——
   fakellm 同款纪律）；无 config 用内置固定结果（demo 用）。不做 delay（timeout 测试用
   测试内联慢 provider，不污染 fake）。
5. **webSearchTool**：声明 name `web_search`、description（上游原句 + cite 指引并入）、
   parameters `{query}` required；execute：query trim 空 → `{error:'query must be a
   non-empty string'}`；自建 timeout signal → `ctx.web.search({query, maxResults},
   signal)`；WebError → `{error: message}`（不 crash——稳定注册）；成功 → 结构化结果
   原样返回；意外错误上抛。注册无条件执行（provider 缺失/不可用不影响注册）。
6. **deepseekWebSearch**：id `'deepseek-official'`；config 默认值全部上游同款
   （baseURL `https://api.deepseek.com/anthropic/v1`、model `deepseek-v4-flash`、
   apiVersion `2023-06-01`、maxTokens 4096、maxUses 5、apiKeyEnv `DEEPSEEK_API_KEY`、
   env 兜底 `DEEPSEEK_SEARCH_BASE_URL`）+ `fetch?` 注入（假 HTTP 测试）；available()
   本地检查；search() 错误映射/严格模式/去重/省略空字段全部按上游事实实现。
7. **零 key 闭环**：假 LLM 台词本 → web_search → fakeWebSearch 固定结果 → tool 事件
   入轨迹可回放；e2e 真 ctx 组装全链路。
8. **Web 接入（M8 教训）**：web-demo-shared 挂 webRuntime + webSearchTool；fake 模式
   挂 fakeWebSearch，real 模式挂 deepseekWebSearch（无 key 时 available()=false →
   模型调 web_search 得 `{error}` 结果——稳定注册在浏览器可见；有 key 即真搜索）。
   fake 台词本第三轮 = web_search 场景；回归 `packages/web/tests/web-demo-m10.test.ts`。
9. **demo**：`pnpm demo:websearch`（`packages/web-search/examples/websearch-demo.ts`），
   三幕零 key（M9 骨架）：装载后 tools.list() 出现 web_search → 假 LLM 驱动真工具调用
   全程入轨迹 → 卸载 provider 后调用得 `{error}`（工具仍在）→ 重装恢复。
10. **教程** `docs/tutorials/M10-web-search.md`（slug 与 requirements §9 一致），练习
    `my-provider.test.ts`（写自己的 provider 注册进 webRuntime：断言唯一自动选择 +
    maxResults 截断 + 红绿翻转——删 available() 看选择失败的 WebError）。
