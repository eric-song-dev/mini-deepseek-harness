# Web 布局：聊天区独立滚动，trace 常驻视口（2026-08-16）

## 症状

聊天消息变长后，中间聊天区没有自己的滚动条；页面整体被撑高，底部 extras
（轨迹 trace）区被挤出视口看不到。

## 根因

`.dsh-shell` 网格行是 `1fr auto`，但网格项 `.dsh-area` 默认 `min-height: auto`：
第 1 行被聊天内容撑破 `100vh`，整页滚动；`.dsh-messages` 的 `overflow-y: auto`
因父链高度未受约束而从不生效（滚动条轮不到它出现）。

## 决策：三环高度链（纯 CSS，壳与组件一行不改）

1. `.dsh-area` 加 `min-height: 0` —— 网格项允许低于内容高度；
2. `.dsh-conversation` 由 `height: 100%` 改为 `flex: 1 + min-height: 0`
   —— 填满区域且可收缩，摆脱百分比高度解析依赖；
3. `.dsh-messages` 维持 `flex: 1; overflow-y: auto` —— 至此获得确定高度，
   长聊天在消息区内部出滚动条。

三个主区域（列表/对话/工具）共用同一套「区域 min-height:0 + 面板内部滚动」模式。

## 测试

jsdom 无布局引擎，无法断言真实滚动行为；在 apps/web 构建冒烟测试中把
「高度链三段声明」作为回归守护（构建产物 CSS 断言）。真浏览器人工验收
交给 demo（长聊 + trace 同在视口）。
