# M10 web search：技术决策（已落地）

- **日期**：2026-08-18
- **状态**：`implemented`（M10 完成；上游调研见同目录 `2026-08-18-m10-web-search-上游调研.md`）

## 背景

M10 = web search 插件（原 M11 重编号，见 `2026-08-18-m10-plan-todo-退回-backlog.md`）。
可插拔机制已在 M0/M3/M6 实现，本 M 只做能力：上游 `ctx.web` 三层架构（能力 seam +
provider 插件组 + 消费方工具）的 mini 版，mini 的第一个外部 HTTP 工具与第一个多
provider 注册表 seam。

## 决策（spec 拍板十项，逐条落地）

1. **单包** `packages/web-search`（`@mini-dsh/web-search`）：mini 包粒度 = 子系统粒度
   （M9 同款）；三层在包内文件边界体现（`web.ts` seam / `fake.ts` / `deepseek.ts` /
   `tool.ts`），换 provider = 加一个文件 + profile 加一行。
2. **服务键 `web`**（上游对齐）：`webRuntime` 插件 `ctx.provide('web', ...)`（config
   `{ searchProvider? }`）；`webSearchTool` `inject: ['tools', 'web']`；两个 provider
   插件 `inject: ['web']`。全仓 grep 证实无键冲突（mini 的 packages/web 不占 'web'）。
3. **Seam 契约**（与上游 type-equiv 同构）：WebSearchRequest{query, maxResults?} /
   WebSearchResult{content?, sources, truncated} / WebSearchSource{url, title?, snippet?,
   publishedAt?} / WebSearchProvider{id, available(), search(req, signal?)} /
   WebRuntime{registerSearchProvider→Unregister, search} / WebError{code}。
   注册重 id 抛 `WEB_DUPLICATE_PROVIDER`；search 六支选择 + 返回路径强制 maxResults
   （截断 + `truncated = 提供方值 || 本次截断`）；signal 原样透传。
4. **fakeWebSearch**（mini 专属）：id `'fake'`，available() 恒 true；台词本
   `results?: WebSearchResult[]`（按序消费，耗尽抛 FakeWebSearchExhaustedError——
   fakellm 同款纪律）；无 config 用内置固定结果（demo 用）。
5. **webSearchTool**：声明 name `web_search`、description（上游原句 + cite 指引并入——
   mini 无 system-prompt seam）、parameters `{query}` required（上游 catalog 同款）。
   execute：query trim 空 → `{ error: 'query must be a non-empty string' }`；自建
   AbortController + setTimeout(searchTimeoutMs, 默认 30000) 作协作式超时 signal →
   `ctx.web.search({query, maxResults}, signal)`；WebError → `{ error: message }`
   （稳定注册不炸轮）；成功 → 结构化结果原样返回（mini 无 output.render 层——轨迹面板
   直接展示 result JSON）；其他错误上抛。注册无条件执行 + ctx.effect（M6）。
6. **deepseekWebSearch**：id `'deepseek-official'`；config 默认值全部上游同款
   （baseURL `https://api.deepseek.com/anthropic/v1`、model `deepseek-v4-flash`、
   apiVersion `2023-06-01`、maxTokens 4096、maxUses 5、apiKeyEnv `DEEPSEEK_API_KEY`、
   env 兜底 `DEEPSEEK_SEARCH_BASE_URL`——不复用 `DEEPSEEK_BASE_URL`）+ `fetch?` 注入
   （假 HTTP 测试，llm adapter 同款）；available() 本地检查（key + URL.canParse +
   正整数上限，禁网络）；search() 错误映射/严格模式（无块抛 WEB_PROVIDER_ERROR 不降级）/
   citation 按 URL 关联/去重/空字段省略全部按上游事实实现。无 credentials seam（key
   直接读 config.apiKey ?? process.env，每次 search 现读）。
7. **零 key 闭环**：假 LLM 台词本 → web_search → fakeWebSearch 固定结果 → tool 事件
   入轨迹可回放；e2e 真 ctx 组装全链路（`tests/e2e.test.ts`）。
8. **Web 接入（M8 教训）**：web-demo-shared 挂 webRuntime + webSearchTool；fake 模式
   挂 fakeWebSearch，real 模式挂 deepseekWebSearch（无 key 时 available()=false →
   模型调 web_search 得 `{error}` 结果——稳定注册在浏览器可见；有 key 即真搜索）。
   fake 台词本第三轮 = web_search 场景；回归 `packages/web/tests/web-demo-m10.test.ts`；
   client 零改动。
9. **demo**：`pnpm demo:websearch`（`packages/web-search/examples/websearch-demo.ts`）
   三幕零 key：四行插件即获能力 → 模型调用入轨迹 → 卸载 provider 得 `{error}` + 重装
   恢复。另附 `examples/websearch.profile.yml` + `plugins/`（default 导出 shim ×4）——
   `loadProfile` 验收"加插件行即获能力"（`tests/e2e.test.ts` 第三条）。
10. **教程** `docs/tutorials/M10-web-search.md`（六要素齐 + 练习 my-provider.test.ts
    红绿翻转实测）。

## 实施修订（相对 spec 定稿）

- deepseek.ts 的 `signal?.aborted` 检查抽成 `isAborted()` 函数——TS 对同一属性检查的
  窄化误报（noUncheckedIndexedAccess 下 catch 块里重复判断被判"无重叠"）。
- 测试假 fetch 的脚本耗尽改为抛 TypeError（而非返回 undefined）——类型上更诚实
  （`typeof fetch` 要求 Promise<Response>），行为上更接近真网络故障。

## 覆盖缺口（指名）

- real 模式（demo:web）挂 deepseekWebSearch 的浏览器人工验收留给用户实测（无 key 时
  模型调 web_search 得 `{error}`；有 key 时真搜索）——自动测试已覆盖其假 HTTP 链路。

  由 my-provider.test.ts 全绿锁定。
