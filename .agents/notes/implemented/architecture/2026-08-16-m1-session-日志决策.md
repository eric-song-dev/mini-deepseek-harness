# M1 技术决策：事件词汇、emit→append 桥接、JSONL 后端、崩溃恢复语义、会话隔离

- **日期**：2026-08-16
- **状态**：`implemented`（M1 已完成：58 测试全绿、typecheck 绿、demo 与教程练习实测通过）

## 背景

M1 落地"事件日志是真源"（requirements §2.3）：定义 Session 事件词汇，做出 append-only 日志、
SessionPersistence seam + JSONL 后端、resume 与崩溃恢复。执行依据 `docs/milestones/M1.md`。

## 决策

### 1. 词汇 = cordis 事件名 + 模块增强（照 M0 实证方案）

- `declare module 'cordis' { interface Events { 'turn/start'() ... } }`，事件名即日志条目 `type`。
- 载荷类型随事件名收窄：`user/assistant {content}`、`tool {name,input,output?}`、
  `turn/end {reason: 'done'|'user'|'crash'}`、`turn/start` 无载荷。
- **注意 cordis v4 rc.8 的 emit 签名细节**：第二个重载 `emit(thisArg, name, ...)` 会吞掉
  "对象载荷打头"的调用——所以约定**事件名永远第一参数**（词汇类型已强制此形状；
  错载荷的 `@ts-expect-error` 会因 thisArg 重载而失效，类型层测试只对事件名与缺参生效）。
- 类型层测试手法：`@ts-expect-error`（未声明事件名、缺必填载荷）+ `expectTypeOf`。

### 2. 头记录 session/created 不是事件（由 create 直接写）

- 每个会话 JSONL 首行 `{seq:1,type:'session/created',ts:meta.createdAt,payload:meta}`。
- 它由持久化 `create` 直接落盘、由 `createHeaderEvent(meta)`（events.ts 单一工厂）生成，
  保证"文件首行 == 内存日志首条"不变量。emit 出来会产生鸡生蛋问题（emit 需要会话已存在），
  所以它是日志里唯一不来自事件的记录。

### 3. 桥接模型（emit → append）

- `Session` 构造时在会话自己的 ctx 上为全部词汇名注册监听器，**同步**推内存日志、
  异步链式 `persistence.append` 落盘；`flush()` 等待最近一次写入、`dispose()` = flush + 关 fiber。
- 备选"直接调 session.append()"被否（M1 spec 已拍板）：两套行为路径会让 UI/测试无法统一"看事件"。
- 落盘失败：链上吞掉并 logger.warn，链不断裂（下一次 append 照常）；`flush()` 暴露最近一次失败。

### 4. Session 是插件（openSession）

- `openSession(parentCtx, config)` 内部 `parent.plugin(...)`：会话得到**子 ctx**（继承根服务，
  M2 的 LLM seam 就靠这条链注入）+ **独立 fiber**（dispose 摘除桥接）。
- cordis v4 rc.8 机制实证：`Context.extend` 沿原型链共享服务/事件；`Fiber` 构造时 `runtime` 非空
  才产生子 ctx；`ctx.on` 注册的监听器是 fiber 的 effect，随 fiber dispose 自动摘除；
  类插件声明 `static inject = ['session-persistence']`，`Service` 子类构造器里
  `super(ctx, 'session-manager')` 自提供。

### 5. 会话隔离：每个会话自己的 EventsService（踩坑修正）

- **坑**：子 ctx 沿原型链共享根 ctx 的 EventsService → 并存会话的桥接互相收到对方的 emit
  （demo 一度把 A 会话事件写进 B 会话日志）。先补复现测试（RED），再修复。
- **修法**：`Session` 构造时 `Object.defineProperty(ctx, 'events', { value: new EventsService(ctx) })`
  覆盖继承来的共享实例（ctx 代理不允许普通赋值）。代价：根 ctx 听不到会话内部事件——
  本架构无损失，真源是日志，观察者读日志而非听总线。
- 教训记入 M1 教程 §4.6 与 README："会话隔离（踩过的坑）"。

### 6. seam 契约与 JSONL 后端

- `SessionPersistence`：`locate/create/append/load/list` + `SessionNotFoundError`；
  契约测试写成**可复用套件** `tests/contracts/persistence-contract.ts`（SQLite 后端直接复用）。
- JSONL：每会话一个 `<dir>/<id>.jsonl`；`dir` 默认 `<DSH_HOME 或 ./.mini-dsh>/sessions`；
  写=追加一行（appendFile），读=按行 parse；append 前查文件存在；list 按 createdAt 倒序
  （同毫秒先后不保证，测试只断言集合与单调序）。
- 不做事务：崩溃窗口由恢复逻辑兜底（M1 spec 拍板，教程 tradeoff 展开）。

### 7. 崩溃恢复语义：**未配对的 turn/start**（对 spec 的细化解释）

- spec 原文"以 turn/start 收尾（无配对 turn/end）"——括号内是语义定义，照它实现：
  **最后一条 turn/start 出现在最后一条 turn/end 之后（或没有 turn/end）**，就补一条
  `turn/end {reason:'crash'}`（seq=末尾+1）。初版只认"末尾恰是 turn/start"，被 demo 的真实
  崩溃现场（`turn/start→user` 戛然而止）暴露后按 TDD 修正（先改测试再改实现）。
- 修复放 SessionManager.resume（load → repair → 有修复则 append 落盘 → openSession），
  **不进 persistence seam**——修复是"日志语义"，不是"存储语义"，SQLite 后端不必重复实现。
- 幂等来自修复本身：补写已落盘，下次 load 配对完整。MVP 单轮假设：最多一个未闭合 turn。

### 8. 工程细节

- 示例脚本放 `packages/session/examples/`（与 M0 的 `packages/kernel/examples/` 一致），
  与 M1 spec 里写的根级 `examples/` 不同——**spec 与既有约定冲突时以仓库约定为准**，已记录。
- 演示 `roundtrip.ts` 三幕（正常落盘/模拟崩溃/重启 resume）+ 教程练习 `my-crash.ts`
  （SIGKILL 真自杀）与 `my-resume.ts`；根脚本 `pnpm demo:session`。
- `.gitignore` 增 `.mini-dsh/`（运行时数据不入库）。
- TS 坑：模块级 const 的外层收窄在闭包（函数体）内不保持 → 参数校验放函数内
  （my-resume.ts 的 `requireSessionId()`）；`exactOptionalPropertyTypes` 下可选属性
  不接受 `| undefined` 赋值，成员声明用显式联合。

## 影响

- `packages/session`（词汇/会话/桥接/seam/JSONL/manager/repair + 示例 + 契约测试套件）、
