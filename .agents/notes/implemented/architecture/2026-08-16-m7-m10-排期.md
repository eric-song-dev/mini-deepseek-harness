## 背景

M6（一切注册皆可逆）完成，MVP 全部收口。用户拍板：从 M7 开始优先做四个方向——
①原版 AI 技能移植（学习 upstream 的 `.agents/.claude` 等技能）；②subagent / workflow
（多智能体编排）；③MCP；④plan / todo（原版任务系统，**goal 先不做**）。并要求每个 M
**先读 `../deepseek-harness-upstream` 的源码（文档 + 代码）再开始 mini 版开发**。
随后用户追加：⑤web search 插件（M11）——此前先核实了"插件可插拔"是否已实现。

## 决策

1. **里程碑编号**：M7 = 技能移植（新排期项）；M8 = subagent/workflow（原 backlog #5）；
   M9 = MCP（原 #6 的 MCP 部分，**LSP 留在 backlog**）；M10 = plan/todo（原 #7 的
   plan/todo 部分，**goal 留在 backlog**）；M11 = web search（用户新增项）。其余 backlog
   顺序不变（CLI / 审批栈 / Trajectory v2 / SQLite / goal / LSP / compaction / settings /
   telemetry / 动态插件热加载 / 压轴教程）。
2. **可插拔已实现（核实结论，2026-08-16）**：M0 `packages/kernel/src/profile.ts`
   `loadProfile`（profile.yml 逐行 import → `ctx.plugin()` 组装）+ M3 工具插件（bash/fs
   注册进 `ctx.tools`）+ M5 skill 插件 + M6 注册可逆——加新能力 = 写插件包 + profile
   加一行，loop/kernel 零改动。因此 **M11 不补可插拔基建**，而是用该机制落地第一个
   **外部 HTTP 工具插件**（web search），并示范上游 `ctx.web` 三层架构
   （能力 seam + provider 插件组 + 消费方工具）。
3. **开工协议（写入 requirements §6、references/upstream.md 纪律 4）**：每个 M 开工
   session 先按 `docs/references/upstream.md` 的"M7–M11 上游源码索引"读上游文档与代码，
   记入 notes，再定稿 `docs/milestones/M<n>.md`（draft → proposed），然后编码。
4. **spec 生命周期不变**：M7–M11 的 spec 文件只写概览（draft），任务拆解/TDD 顺序/验收
   由各自开工 session 定稿（milestones/README 已更新此约定）。

## 上游调研摘要（本 session 完成，4 个子代理深读 upstream 源码产出）

- **M7 skills**：`.claude/skills -> ../.agents/skills` 是符号链接别名；SKILL.md =
  frontmatter（`name` kebab + `description` 必填；可选 `whenToUse`/`metadata`/
  `disable-model-invocation`/`user-invocable`；无 version/params；fail-closed 校验）+
  正文。11 个 dsh-* 技能判定：移植 4（code-review / prose-standard / trim-cot-leakage /
  pre-push-checks）+ 可选 3（doc-standards / archive-agent-notes /
  find-simplifications）；其余 4 + 2 个 cordis
  技能依赖上游专有工具链，不移植。**M7 必须同时扩展 mini skill 包**：`Skill` 增
  `description` + frontmatter 解析（content 剥离 frontmatter、name 与目录名校验一致）。
- **M8 subagent/workflow**：四条 seam 最小集——`ctx.subagents`（in-process + `spawn`
  提供方 + one-shot 前台）、`tool-subagent`、`ctx.workflowEngine`（同线程，钩子只做
  agent/parallel/pipeline/phase/log）、`tool-workflow`；子会话 = 独立 Session，父会话只
  记一条 tool 事件。砍：进程外协议全家、worker-thread 隔离、可继续后台子 agent 全家、
  能力矩阵（outputSchema/toolFilter/persona/depthLimit）、UI 全量。loop 零改动。
- **M9 MCP**：上游无独立子系统文档（文档在包内 README + Agent Note
  `2026-07-07-mcp-client-plugin.zh.md`）；MCP 只是"工具生产者"——listTools 分页发现，
  以 `mcp__<server>__<raw>` 命名注册进现有 `ctx.tools`；两阶段同步（fetch→swap）；SDK
  `@modelcontextprotocol/sdk ^1.12.0`。mini 只做 stdio + 一个真 server demo + 可逆 dispose；
  砍 streamable-http、自动重连监督器、OAuth、resources/prompts。
- **M10 plan/todo**：上游没有独立 plan 数据模型——plan 只是布尔协作状态
  （`plan/mode` 事件 + `ctx.planMode` get/set + `plan:policy` 提示词段 + `exit_plan_mode`）；
  任务实体在 todo（`TodoItem` + `todo/write` 整表快照事件 + `todo_write` 工具，均
  log-only）。goal 与 plan/todo 零依赖（源码 grep 证实），mini 不做 goal 不断链。mini 砍：
  pre-step pending 机制、`/plan` 命令、userQuestions 评审流、sessionProjections 注册表。
- **M11 web search**（本 session 直接读上游产出，未派子代理）：上游三层拆分——
  `ctx.web`（dsh-web：提供方注册表 + 执行时选择 + WebError 码表，`registerSearchProvider`
  返回 disposer 与 mini M6 同构）+ provider 插件组（deepseek/perplexity/exa，注册**能力**
  而非工具）+ 消费方 `tool-web`（`web_search`/`web_fetch` 工具，稳定注册）。deepseek
  提供方走 Anthropic 兼容 Messages API + 原生 `web_search_20250305` 服务器工具，解析
  结构化 `web_search_tool_result` 块（绝不从模型文本抓 URL）。mini M11：只做 search +
  `deepseekWebSearch`/`fakeWebSearch` 双提供方 + `web_search` 工具；砍 web_fetch、
  credentials seam、UI web 卡片、perplexity/exa。
