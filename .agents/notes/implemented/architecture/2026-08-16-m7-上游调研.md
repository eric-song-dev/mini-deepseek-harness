## 1. `docs/subsystems/skills.zh.md`（体系总纲）

**照搬的概念（mini 要落地）：**

- skill 名 = kebab-case：`^[a-z0-9]+(?:-[a-z0-9]+)*$`。
- SKILL.md 形态：目录 bundle `<name>/SKILL.md`（可含 references 子资源）+ 平铺 `<name>.md`；不支持递归 `**/SKILL.md`。
- frontmatter 三块语义：
  - 必填 `name`（kebab，与目录/文件名一致）+ `description`（目录/列表**只展示它**，正文与路径从不进目录）；
  - 可选 `whenToUse`、`metadata`；
  - 调用控制 `disable-model-invocation` / `user-invocable`（负向/正向两键）→ 规范化为正向 `{modelInvocable, userInvocable}`，省略默认 true。四种组合都合法（全 false = 仅受信调用方）。
- 摘要 vs 完整定义分离：`SkillSummary`（name/description/whenToUse/invocation）vs `SkillDefinition`（+ content（frontmatter 已剥离）+ path + metadata）。模型会话目录只用 name+description；description 由**消费方**截断（`catalogDescriptionMaxLength` 默认 500）。
- 注册表不缓存完整定义：每次 `get()` 重读正文；名称与候选项不再匹配的定义会被拒绝（fail-closed）。
- 模型可见目录经 XML 转义（mini 的工具结果走 JSON，天然转义，不必专门处理）。
- skill 工具：校验 kebab-case 名 → 目录查找 → `isModelInvocable` 拒绝 → 重读完整定义 → 返回内容。解析不出 → 报告未知/不可用。

**砍掉（mini 不做，M7 spec"明确不做"对齐）：**

- 宿主+scope 分层注册表、rank 多根扫描（100/200/…/600）、runtime register 先到先得、discovery 缓存/快照 complete 语义、`skills/change` 失效事件、AbortSignal 竞争、Chokidar watcher、git-root 探测、`resourceBase` 资源引导（mini 的 references 附件用正文内相对链接 + 一起搬文件即可）。
- mini 的 Skills seam 保持 M5 形态：`register(skill)/list()/get(name)`，`get` 抛 `UnknownSkillError`（比上游返回 undefined 更响亮，M5 已定）。

**挂接点（mini 对应物）：**

- `Skill` 接口扩展 description/whenToUse/modelInvocable/userInvocable → `packages/skill/src/skills.ts`。
- frontmatter 解析 + name 校验 + content 剥离 → `packages/skill/src/fs-discovery.ts`（新 `parseSkillFile`）。
- 目录展示 description → `packages/skill/src/tool.ts`（list 返回 `{name, description}`）。
- 全 false/调用策略：mini 的 tool.get 只按 modelInvocable 过滤（userInvocable 留给未来 CLI slash，M7 只解析存储不消费）。

## 3. `packages/skill/skill-filesystem/README.zh.md`（发现 + **skill 格式规范**）

**照搬（格式契约，M7 的核心）：**

- 形态：目录 bundle `<name>/SKILL.md`（+平铺 `<name>.md`，mini 砍）；不支持递归 `**/SKILL.md`；发现深度一层。
- frontmatter 用 `yaml` 包解析为开放 YAML 对象；必填 `name`（kebab-case）+ `description`；可选 `whenToUse`、`metadata`、`disable-model-invocation`、`user-invocable`。
- 调用字段接受：YAML 布尔 + 不区分大小写的 `true/false`、`yes/no`、`on/off`、`1/0`（字符串也要认 → 解析后需 `frontmatterBoolean` 规范化）。
- 省略调用字段 → 默认允许（输出两个正向值，全缺省也输出 `{modelInvocable:true, userInvocable:true}`）。
- **fail-closed（失败时默认拒绝）**：驼峰 legacy 键或非布尔调用值 → 警告并**排除整个 skill**（不是丢字段、不是宽松默认）——因为忽略无效数据可能在已禁用的接口上暴露 skill。类型错误的 `whenToUse`/`metadata` → 省略字段（不授予调用权限，故不必排除）。
- name 必须 kebab-case；frontmatter 的 name 与目录名/文件名不一致 → 拒绝（陈旧名称/改名后拒绝并失效）。
- 目录与正文生命周期分离：发现解析 frontmatter 出摘要；每次 `get` 重读重解析当前文件（正文编辑无需失效通知）。
- 格式错误/非文本条目 → 警告 + 跳过（模型目录收不到每个 skill 的诊断）；已确认缺失的路径是合法空状态。

**定夺候选（写入 spec 定稿）：**
1. YAML 解析用 `yaml` 包（上游同款；手写子集解析器在布尔宽松语义上有风险，教学价值不如 seam 本身）。
2. mini 的 fail-closed 语义：解析失败/name 缺失或非 kebab/name 与目录不符/驼峰 legacy 键/非布尔调用值 → **该条目从发现结果中排除**；`discoverSkills` 沿 M5 惯例（跳过非 skill 目录）——具体"警告+跳过 vs 抛错"待读完 src 后契约定夺（M7 draft 写"name 不匹配报错、坏 frontmatter fail-closed"）。
3. description 截断 500：上游由消费方（tool）配置；mini 的 skill 工具 list 时截断 500。

## 4. `packages/skill/skill-filesystem/src/index.ts`（核心实现，~L909 起）

**照搬（实现级契约）：**

- `parseFrontmatter(raw)`：首行必须恰为 `---`（去 `\r`）；找下一个独立成行的 `---` 闭合；中间段用 `yaml` 包的 `parse` 解析，须为普通对象（null/数组不算）；body = 闭合行之后全文。无 frontmatter/无闭合 → undefined。
- `parseSkillFile` 校验顺序（上游 fail-closed = **警告 + 跳过该条目**，不是抛错）：
  ① frontmatter 缺失/坏 YAML → 警告跳过；② `name`/`description` 缺失（`stringField`：非空字符串）→ 警告跳过；③ name 非 kebab（`^[a-z0-9]+(?:-[a-z0-9]+)*$`，即 `isSkillName`）→ 警告跳过；④ `parseInvocationPolicy` 抛错 → 警告跳过。content = `parsed.body.trim()`。
- `parseInvocationPolicy`：先 `rejectLegacyInvocationKey` 三个驼峰 legacy 键（`disableModelInvocation`→`disable-model-invocation`、`modelInvocable`→`disable-model-invocation`、`userInvocable`→`user-invocable`，命中即抛 "unsupported; use ..."）→ `frontmatterBoolean` 读两键 → `modelInvocable = disable !== true`、`userInvocable = user !== false`（undefined 默认允许）。
- `frontmatterBoolean`：hasOwn 才处理；boolean 直通；`1`/`'1'`→true、`0`/`'0'`→false；字符串（不区分大小写）true/yes/on→true、false/no/off→false；**其他一律 throw `must be a boolean`**。
- `optionalString`（whenToUse）：非空字符串才保留；`optionalMetadata`：纯对象才保留。类型错 → 省略（不授调用权，不排除条目）。
- 发现层：目录项 `<name>/SKILL.md`；`parseSkillFile` 返回 undefined 的条目 `continue` 跳过；按名排序。
- **上游没有"frontmatter name == 目录名"的发现期校验**——注册表/加载期按请求名校验定义名（`loaded skill has invalid name`）。mini 更严：发现期直接校验 `parsed.name === 目录名`（M7 draft 已预拍板"name 与目录名校验一致"），更简单且防歧义——记入教程 tradeoff。

**砍掉：** Chokidar watch 全家、findProjectRoot/git 探测、rank 多根、ctx.fs 回退、signal 竞争、symlink 处理、`isPotentialSkillPath`（观察路径用）。

## 9. 定稿决策摘要（spec 引用本文）

- YAML 解析用 `yaml` 包（上游同款；手写子集解析器在布尔宽松语义上有风险）。
- 坏条目语义：**fail-closed + 响亮**——`discoverSkills` 遇到坏 frontmatter/name 不匹配/legacy 键/非布尔调用值**抛 `InvalidSkillError`**（带路径与原因），与 M5 "路径是文件 → 报错" 先例一致；上游的 warn+skip 是为多 provider 生产环境，mini 是单根开发者自管仓库——这一偏离写入 spec 与教程 tradeoff。
- name 与目录名校验：发现期即校验 `frontmatter.name === 目录名`（上游只在加载期按请求名校验；mini 更严更简单）。
- 工具过滤与截断：list 只含 modelInvocable 技能、description 规范化（空白折叠+trim）后 500 截断（`slice(0,497)+'...'`）；get 先 kebab 校验再查表再 modelInvocable 过滤（消费方边界纪律，两处校验）。
- mini 的 `Skill` 增 `description`（必填）+ 可选 `whenToUse`/`modelInvocable`/`userInvocable`（register 规范化默认 true）；`metadata` 不引入（忽略该键）。
