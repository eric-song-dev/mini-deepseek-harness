# M4 Web 技术决策

- **日期**：2026-08-16
- **状态**：`implemented`（M4 已实现并通过验收）
- **背景**：M4 把 M1–M3 的能力（会话、loop、工具）暴露成远程操作，让浏览器完成一次
  "真实对话"。spec 预拍板了 8 条关键设计决策，实施过程中逐条核对，以下为落地结论。

## 决策

### 1. 桥协议：三种消息 + requestId 配对（spec 决策 1 落地）

- client→host：`{kind:'request', requestId, method, params}`；
- host→client：`{kind:'response', requestId, ok, result|error}` 与
  `{kind:'event', sessionId, event}`（event 载荷即日志条目，seq/ts/payload 原样）。
- 坏形状消息回 `BadRequestError`（能识别 requestId 就带回，否则 'unknown'）；WS 传输层
  JSON 解析失败以 `{kind:'bad-message'}` 标记交给桥应答（不断线）。
- 失败应答 error 携带 `{name, message}`——client 侧转 `RpcError`（name 保留，可
  `toMatchObject({name:'SessionNotFoundError'})` 式匹配）。

### 2. 桥是 seam：内存直连是测试传输，WS 是生产传输（spec 决策 2 落地）

- `RpcBridge`（handle/pushEvent/accept/connectionCount）+ `BridgeConnection`
  （send/onMessage/onClose/close）与传输无关。
- `memoryConnectionPair()` 造一对已连接的内存连接（同进程零网络）；`attachWsBridge`
  把 WebSocketServer 包装成连接。client 组件测试（jsdom）全部走内存直连 + 真 host
  内存桥，零端口、毫秒级。

### 3. 定夺点 A 落地：loop 与桥靠"session/append 事件"对接，loop 本体一行不改

- session 包新增**不落日志**的运行时事件 `session/append`：日志每追加一条同步发出
  （载荷是刚追加的完整条目）。
- host 侧 `attachSession` 在会话 ctx 上挂适配：监听 `session/append` → `bridge.pushEvent`。
- loop 只加了 `AgentLoopConfig.stream`（默认关）：开启时 `llm.chat` 传 `onChunk`，
  分片经 `assistant/stream` 事件落日志。非流式实现无分片 → 只有 assistant 终事件，
  client 渲染自动回退（spec 决策 3 的"非流式回退"）。

### 4. 定夺点 B 落地：自动化 e2e = 真 host + 脚本化 WS 客户端，不开真浏览器

- `packages/web/tests/e2e.test.ts`：真 HTTP+WS（port 0）→ list → create → send
  （工具往返 + 流式分片）→ 断言完整事件序列与 tool 卡片数据 → 断线重连 → resume
  历史完整 → 续聊。浏览器人工验收交给 demo 与教程练习。

### 5. 流式分片是日志真源的一部分（词汇增量 assistant/stream）

- `assistant/stream` 进词汇表与 SESSION_EVENT_NAMES：落内存日志 + JSONL，resume 可重放。
- `projectMessages` 跳过它（模型输入用最终 assistant 全文）；client 的
  `projectConversation` 用它做"打字中"气泡（assistant 终事件封印成全文）。
- adapter 流式：onChunk 传入时 `stream:true` + `stream_options.include_usage`，SSE 逐行
  解析（含 tool_call 增量按 index 累积、usage 收尾帧）；非流式路径字节不变。
- 假 LLM 台词本：`chunks`（分片序列）+ `chunkDelay`（每片间隔），与 toolCalls 互斥
  （同时给出即脚本错误）；未传 onChunk 时静默拼全文。

### 6. 契约修订：session.create 返回 `{meta, events}`（与 resume 对称）

spec 的最小集写"create 返回 meta"；实施时 client 需要头记录初始化视图，改为与
resume 同形 `{meta, events}`（events 至少含 session/created 头记录）。RPC 方法仍是最小集
（list/create/resume/send），无新增方法。

### 7. client 侧三处结构性决定

- **ClientBridge 结构化类型，不 import web 包**（fakellm 不 import llm 同款手法）：
  client 零运行时依赖 web，浏览器 bundle 不会拉进 node 代码。
- **cordis 惯用 DI，而非 M2 的 defineProperty 遮蔽**：ui 插件
  `inject:['slot-registry']` 取注册表；渲染代码（React 组件在插件作用域外）经
  `ctx.get(...)` 取服务；`SlotContext` 直接携带 store（组件不摸 cordis）。
  M2/M3 的 defineProperty 是"并存会话撞键"的特例解法，client 单实例无此问题，
  走正路更有教学价值。
- **ClientRoot 的 extras 区**：主布局只认三个 slot（session-list/conversation/tool），
  其余已注册 slot 依注册顺序进 extras 区——兑现"未来任意 ui-* 插件从 Slot 挂进来，
  不改 shell"。section 带 `data-slot` 属性（断言与练习翻转依赖它）。

### 8. vitest workspace 拆分（spec 决策 7 落地）

`vitest.config.ts` → `projects: [node, dom]`：node 跑 host/agent/session 等与
apps/web 构建冒烟；jsdom 跑 client（组件 + UI 装配 + 教程练习测试）。互不污染环境。

### 9. demo：循环台词本 6 轮

假 LLM 台词本（bash echo 工具往返 + 5 分片流式回答）重复 6 轮，demo 期间可反复对话；
用完 turn/end(crash) 报错，重启即可。`demo:web` = build:web + 起 host（静态文件 +
WS 同端口）。

## 影响

- `packages/session`：词汇增 `assistant/stream`、运行时事件 `session/append`。
- `packages/llm`：ChatOptions.onChunk 由"预留"转正；adapter SSE 流式；seam 契约测试
  增流式 case（makeStreaming）。
- `packages/agent`：AgentLoopConfig.stream（默认关，M2/M3 行为不变）。
- 新包 `packages/web` / `packages/client` / `packages/bundle-web` + `apps/web` 壳。
- 测试基建：vitest 双 workspace、jsdom 依赖。

## 遗留问题

- 桥不分频道/无鉴权/明文（迷你版取舍，教程 4.6 明示；backlog 方向）。
- `assistant` 事件 payload 暂无 token 用量（M2 的 usage 未落日志）——M5 的轨迹检查器
  要显示 token，需在 M5 给 assistant payload 增 usage（可选字段，兼容旧日志）。
- M5 轨迹回放需决定 assistant/stream 分片的展示（聚合 or 逐片重放）。
