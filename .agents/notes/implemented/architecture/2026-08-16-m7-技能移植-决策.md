# M7 决策归档：原版 AI 技能移植（SKILL.md 格式契约 + mini 化改写）

- **日期**：2026-08-16
- **状态**：`implemented`（M7 已实现并通过验收；上游调研全过程见
  `implemented/architecture/2026-08-16-m7-上游调研.md`，spec 定稿见
  `docs/milestones/M7.md`）
- **背景**：M5 交付了 Skills seam（机制），但 `fs-discovery` 不解析 frontmatter——
  `tdd` 技能的 frontmatter 被忽略、content 混着 `---` 元数据块，`skill` 工具
  list 只返回名字，模型无法按 description 路由。本 M 学上游 `.agents/skills`
  体系（SKILL.md 格式 + 发现约定），补"原版技能内容 + 格式契约"。
- **上游索引**：`docs/references/upstream.md` §M7（全部按序读完，一次一个文件）。

## 决策（预拍板七条全部落地，与上游核对后）

1. **YAML 解析用 `yaml` 包**（v2.9.0，`packages/skill` 依赖；上游同款）。手写子集
   解析器在宽松布尔语义（`yes/no/on/off/1/0`）上有风险，教学价值不如 seam 本身。
2. **坏条目 fail-closed + 响亮**：坏 frontmatter / 缺 name 或 description / 非 kebab
   name / name 与目录名不符 / 驼峰 legacy 键 / 非布尔调用值 → `discoverSkills` 抛
   `InvalidSkillError`（消息带文件路径与原因），发现中止。**对上游"警告 + 跳过"
   的有意偏离**：上游是多 provider 生产环境（一个坏技能不杀 agent），mini 是单根
   开发者自管仓库——坏 skill 与坏 profile 一样是配置错误（M5"路径是文件 → 报错"
   先例）。教程 §4.2 解释。
3. **name 与目录名校验在发现期做**：`parseSkillFile(raw, 目录名)` 即校验
   `frontmatter.name === 目录名`。上游只在加载期按请求名校验；mini 更严更简单——
   发现期只留一个可寻址名字。
4. **`Skill` 契约扩展**：`description: string` 必填 + 可选 `whenToUse` /
   `modelInvocable` / `userInvocable`（register 校验 + 规范化默认 true，`get` 恒返回
   两布尔）。不引入 `metadata`。`createSkillsRegistry.register` 校验 kebab name /
   非空 description / 布尔调用值；重名仍抛错（M5）、撤销语义不变（M6）。
5. **消费方边界纪律**：`SkillsService.get` 是受信原语不过滤；`skill` 工具 list 只含
   modelInvocable 技能、get 先 kebab 校验 → 查表 → modelInvocable 过滤（false →
   `{ error }` 结果）。description 截断 500（空白折叠 + `slice(0,497)+'...'`）在消费方
   （上游 catalogDescription 同款）。
6. **不引入 `<skill_content>` 包装**：mini 的 wire 是 JSON（M5 契约），`get` 结果
   `{ name, description, content }` 已结构化。上游 renderSkillContent 的"共享渲染
   真源"概念记入教程，留给未来第二条加载路径（slash 菜单）。
7. **移植 6 技能**（第一梯队 4 + 第二梯队 2，find-simplifications 不移植）：
   `code-review` / `prose-standard`（+references/examples.md）/ `trim-cot-leakage`
   （+references/examples.md + recall-batteries.md）/ `pre-push-checks` /
   `doc-standards` / `archive-agent-notes`。全部去 `dsh-` 前缀、全中文、引用 mini
   对应物（requirements/notes/tutorials/`pnpm test`/`pnpm typecheck`）。`tdd` 文件
   不动（已有合法 frontmatter，解析器升级即兼容）。
