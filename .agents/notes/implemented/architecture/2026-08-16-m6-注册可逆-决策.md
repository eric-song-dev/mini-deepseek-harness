# M6 注册可逆决策记录

- **日期**：2026-08-16
- **状态**：`implemented`
- **spec**：`docs/milestones/M6.md`

## 背景

用户指令：审计并修复"所有注册是否可逆"。审计结论（本 session 实测复现）：
cordis 托管的注册（`ctx.provide`/`ctx.plugin`/`ctx.on`）与 webHost 的服务器收尾
天然可逆，但**自建注册表全部不可逆**——Tools/Skills/RpcBridge/SlotRegistry 只有
register 没有撤销；client 订阅链（store→bridge→transport）退订函数被丢弃；
webHost 4 个 RPC handler 裸注册；Session 卸载不排空落盘；loop 句柄不随 fiber 摘除。
实测：卸载 bashTool 的 fiber 后 `tools.list()` 仍含 bash 且可 execute。

## 决策（M6 spec 预拍板七条，实施中逐条核对）

1. **统一模式"注册返回幂等撤销函数 + 注册方挂 ctx.effect"**。撤销函数闭包持有
   被注册对象，删除前校验"仍是同一个对象"（同名重注册后不误删新项）；幂等。
2. **client 订阅链清理归 clientShell（装配者）**：store 增幂等 `dispose()`；
   `createBridgeClient` 持有 `offMessage`/`offClose`，`close()` 幂等（拒绝未决
   请求→清订阅→摘监听器→关 transport，且 close 后新请求立即 reject）；
   wsClientBridge 的 open 监听器一次性（open 后即摘）。
3. **webHost 4 个 handler 挂 effect**：注入桥路径（测试/未来 HMR）也必须正确撤销。
4. **会话卸载 = 落盘排空**：`ctx.effect(() => () => this.flush())`。实施中实证
   cordis rc.8 的 `_unload` 会 `await` 全部 disposable 清理（含返回 Promise 的），
   因此 flush 排空是确定性的——测试用 50ms 慢后端锁定。
5. **agent-loop 句柄对称撤销**：`ctx.effect(() => () => Reflect.deleteProperty(...))`；
   测试用 `getOwnPropertyDescriptor` 断言（fiber 死后 Proxy 直接访问会抛
   "without inject"，descriptor 走 target 不受影响）。
6. **HMR-safety 测试组**（上游 testing.md 纪律）：每个注册表一组
   （tools/skill/web/client/session/agent 各 `tests/reversibility.test.ts` 或
   等价用例）；seam 契约测试（tools/skills）同步增撤销语义。
7. **不做 HMR 运行时本身**（backlog #11 前置已备）。

## 影响

- `@mini-dsh/tools`：`register`/`addHook` 返回 `Unregister`；四工具插件挂 effect。
- `@mini-dsh/skill`：`register` 返回 `Unregister`；skillTool 挂 effect。
- `@mini-dsh/web`：`handle` 返回 `Unregister`；webHost 挂 effect。
- `@mini-dsh/client`：slot 撤销 + `registerSlot` 助手（放 shell.ts，保持 slots.ts
  框架无关）+ store.dispose + bridge close 幂等清理 + ws open 一次性。
- `@mini-dsh/session`：卸载 flush 排空（cordis await effect cleanup 的实证点）。
- `@mini-dsh/agent`：loop 句柄随 fiber 摘除。
- 测试：全仓 271 → 288（+17，含 4 个教程练习文件）；dom/node 双 workspace 全绿；
  typecheck 全绿。
