## 决策（spec 预拍板九条逐条核对）

1. **fork 纳入 M8** ✓：`completedTurnPrefix`（父日志截至最后 `turn/end` 的轮次事件，
   不含父头记录）+ `inheritsParentContext` 措辞切换；种子经 `create({ seed })` 持久化
   （头记录占 seq 1，种子平移 2..N+1，`SessionManager` 负责重编号），resume 重放同
   前缀——假 LLM 断言"子 agent 第一次调用看到父历史"。
2. **parent = 父会话 ctx**（draft 修订）✓：`ToolContext` 增可选 `agent?: Context`
   （tools 包类型演进）；loop 一行透传 `{ cwd, agent: ctx }`。全 M8 对 loop 的改动
   **仅此一行**（diff 可查：`packages/agent/src/loop.ts`）。provider 从 parent ctx
   读 `session-log`/`session-meta`；观察事件 emit 在 parent ctx 隔离总线。
3. **stopReason `completed|aborted|error`** ✓：turn/end done→completed、limit/crash→
   error；aborted 只从启动前 signal 中止进入 start 拒绝路径（mini loop 无中途取消，
   已知限制注释在 providers.ts 头）。
4. **谱系只记账不设限** ✓：`SessionMeta.parentSessionId`/`depth`（旧会话缺省 = 顶层）。
5. **观察事件 emit 位置** ✓：subagent/start|end 成对（同 runId+provider+childId，end
   带 stopReason + 最后输出）emit 在父会话 ctx；provider-added/removed emit 在服务
   ctx；workflow/* 六事件同父会话 ctx；`workflow/end` 无 value；agent 按 seq 配对；
   监听器异常容器化（try/catch + logger.warn）。
   **2026-08-18 增补**：subagent 服务的 emit 同样补上异常容器化 + 先挂配对观察再 emit
   start（初版漏了，审计发现两处不一致）——见 `2026-08-18-bugfix-六项修复.md` 第 6 项。
6. **workflow 同线程 `async Function`** ✓：meta 校验 + 脚本 parse 先行（同步失败不
   发布 run）；脚本 realm 只注入 `args` + 五钩子；返回值 JSON-serializable 校验
   （RESULT_UNSERIALIZABLE）；result 从不 reject；cancel 只在钩子 await 点生效；
   dispose 幂等；"同线程 ≠ 沙箱"注释与教程写明。
7. **WorkflowError(fatal) 纪律** ✓：码表 mini 子集（SCRIPT_PARSE/META_INVALID/
   INVALID_ARGUMENT/UNSUPPORTED_OPTION/AGENT_START/RESULT_UNSERIALIZABLE/CANCELLED）；
   parallel/pipeline 对 fatal re-throw、逐项 null 只给普通错与子失败。
8. **工具措辞** ✓：tool-subagent 按 inheritsParentContext 换 description；tool-workflow
   的 description 即脚本编写契约全文（与引擎实现同步）。
9. **包布局** ✓：`packages/subagent`（seam+spawn/fork+工具）、`packages/workflow`
   （引擎+工具）；bundle-web 不接（子会话经现有会话列表回放，M8 验收不含 Web 演示）。

## 实施修订（定稿后新增的边界决定）

1. **子任务 tool 结果不落父日志**：child crash 时父日志 tool 结果事件缺省（execute
   抛错 → loop crash），与 M3 未知工具行为一致；父日志结尾 turn/end(crash) 保留
   "绝不静默成功"证据。
2. **并发子 agent 与共享假 LLM 的台词顺序竞态**：parallel 下两个子会话共享同一 fake
   LLM 实例，回复按完成顺序弹出——e2e/练习用"相同回复"断言，避免与调度顺序耦合
   （真实部署中共享 llm 服务无此问题，因为真模型无预置台词）。
3. **workflow result.error 带 code 前缀**（`CODE: message`）：WorkflowError 的机器可
   路由码进 error 文本，模型/消费方可据码纠正（上游 error 文本无码，mini 更利于教学
   演示 fatal 纪律）。
4. **agentsStarted 只计被接受的调用**：fatal（拼错选项）在计数之前抛出；parallel
   中并行的合法 agent() 已被接受则仍计数（教程练习 2 的答案 1 即此语义）。
5. **mini tool-workflow 无 render 层** → maxResultChars 无消费方，砍（spec 草案含该
   配置；Web tool 卡片直接显示 JSON 结果）。工具结果 shape 保持上游规范值
   `{runId, agentsStarted, result}`。
6. **修订决策 9（2026-08-16，用户质询"你为啥这么做"）**：初版"bundle-web 不接"是
   定稿时把 draft 的"砍 UI 全量"（只砍 ui-subagent 目录树 / ui-workflow-run Chat
   节点）扩大解释成了"整个 Web 不接"——与 draft 目标 4"轨迹面板可导航到子会话回放"
   和项目 Web-first（P0）定位矛盾：不接则 demo:web 永远产生不了子会话，导航回放
   是空话。修正 = **demo runtime 挂 host 侧插件、client 零改动**：
   `web-demo-shared.ts` 挂 SubagentRuntime/spawnProvider/forkProvider/toolSubagent/
   WorkflowEngine/toolWorkflow（fake/real 两种模式都挂）；`fakeWebDemoReplies()`
   第一轮改为 subagent 委派场景（父调 subagent → 子跑 bash date → 子回答 → 父汇报，
   共 4 条台词 + 后 5 轮 bash+流式）；`web-demo-fake.ts` 横幅说明浏览器验收路径；
   新增回归 `packages/web/tests/web-demo-m8.test.ts`（工具在列 + 父 tool 事件含子
   会话 id + RPC 会话列表出现子会话、谱系正确、独立可回放）。教训：砍 UI 插件 ≠
   砍能力接入；Web-first 项目的每个 M 至少要有一条浏览器可见的验收路径。
