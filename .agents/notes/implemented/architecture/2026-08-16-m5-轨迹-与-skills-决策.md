## 核对结论（逐条，含实施中的修订）

1. **Trajectory 投影放 session 包**（决策 1，无修订）：
   `projectTurns(events)` 落在 `packages/session/src/turns.ts`，与 M2 的 `projectMessages`
   （输入侧）并列成输出侧视图。输出结构：
   `ProjectedTurn { index, userText, startedAt, endedAt, durationMs, endReason, events }`，
   轮内 `ProjectedTurnEvent { seq, type, ts, durationMs, payload }`。
   client 轨迹面板、demo、测试共用同一投影（"日志真源 → 投影 → 视图"三件套在代码上
   就是 session（投影）→ client（视图））。

2. **token 数据落日志**（决策 2，细化 ⚠️）：`AssistantEventPayload` 增可选 `usage`。
   定夺：类型**在 session 本地定义**（`SessionUsage { inputTokens, outputTokens }`，与
   llm 包 `ChatUsage` 结构化兼容）——沿用 `ProjectedToolCall` 的既有模式，session 不
   依赖 llm（会话包是全仓地基，只被依赖）。loop 无条件写 `usage: result.usage`
   （流式/非流式都写；fakellm/真 adapter 都返回 usage）。旧日志（M2–M4）无此字段，
   投影原样保留载荷、检查器兜底显示 `—`。耗时一律由事件 ts 差算出，不另存字段。

3. **流式分片聚合展示**（决策 3，细化 ⚠️）：连续 `assistant/stream` 合成**一条**摘要行，
   `type: 'assistant/stream'`、`payload: { chunks: string[], joined: string }`。
   定夺：行 `ts` 取首片 ts、`durationMs` = 末片 − 首片（行自身跨度），后续事件的
   durationMs 从末片算起——整轮 durationMs 恒等于 endedAt − startedAt，总量守恒。
   assistant 终事件仍是独立行。逐片回放动画放 v2（backlog #3）。

4. **Skills seam**（决策 4，无修订）：`SkillsService { register / list / get }`，
   语义定夺：`get` 未知技能**抛** `UnknownSkillError`（带技能名——seam 对程序调用方
   是响亮的，契约测试守护）；重名注册抛错（防静默覆盖）；`list` 保持注册顺序。
   插件形态 `skillsFromDirectory`（扫描 + 提供）+ `provideSkills`（注入任意实现）。

5. **skill 工具是文档检索**（决策 5，定夺 ⚠️）：声明 `{ name: 'skill',
   parameters: { action: 'list' | 'get', name? } }`。语义定夺——"输出是内容，异常是
   结果"（M3 语义）：正常路径返回**内容**（`{ skills }` / `{ name, content }`）；模型侧
   的"异常"（未知技能、坏参数）返回 `{ error }` **结果**——模型能看到失败原因并纠正
   （同 M3 bash 的"exit code 是输出不是异常"），而不是把整轮炸掉。seam 的
   UnknownSkillError 在工具里转成结果，其他意外错误仍原样上抛。loop 一行不改：
   `skillTool` 插件 `inject: ['skills', 'tools']` 注册进 toolRegistry。

6. **ui-trajectory 走 Slot**（决策 6，无修订）：注册 slot `trajectory` → M4 的 extras
   区全宽面板（左侧按轮事件表、右侧检查器）。shell 与 entry 一行不改——M4 spec 决策 5
   承诺的"未来任意 ui-* 插件从 Slot 挂进来"第一次兑现（bundle-web 只加了一行）。

7. **自举验收路径**（决策 7，无修订）：`packages/skill/tests/bootstrap.e2e.test.ts` 经
   **真 host（webHost 门面 + 内存桥，零网络）** + 真 filesystem 发现（仓库
   `.agents/skills`）+ fakellm 台词（list → get tdd），断言模型收到的 tool 消息
   == `SKILL.md` 文件正文；demo:trajectory 第二幕同款"教模型按 TDD 说话"。

## 实施修订（spec 之外的定夺）

- **a. 断尾与嵌套 turn/start 语义**：投影是纯函数（不能用 Date.now），断尾轮
  `endReason: 'crash'`、`endedAt` 取轮内最后一条事件的结束 ts（"最后证据"）；未闭合的
  轮内又出现新 turn/start 时，旧轮同样按 crash 闭合、新轮照常。修复动作仍归
  `repairDanglingTurn`（M1），投影只读、幂等。
- **b. 事件耗时定义**：轮内首条 `durationMs` 的基准是 turn/start 的 ts；单事件行的
  durationMs 是"距上一条结束的间隔"（行自身是时间点）；聚合行是末片 − 首片。tool
  调用→结果对的耗时由检查器配对时算（结果 ts − 调用 ts）。
- **c. 面板选中态只存 seq**：投影每次重算都换对象标识，组件里按 `selectedSeq` 从最新
  投影找回事件对象（`turn.events.some(e => e.seq === selectedSeq)`）——用对象引用会
  在重投影后失效（jsdom 测试第一版踩到，注释已记录）。
- **d. filesystem 发现边界**：目录不存在 → 空数组（graceful，没装 skill 的系统照常
  启动）；路径是文件（坏目录）→ 报错（响亮暴露配置错误）；非目录项与没有 SKILL.md 的
  子目录跳过；结果按名排序（确定性）。
- **e. usage 契约同步更新旧测试**：M2–M4 的 loop/e2e/web 测试对 assistant 载荷的
  精确断言全部补上 usage（不是放水——loop 消费契约的真实演化，M3 决策 b 同款）。
- **f. 教程练习**：my-skill.ts（自注册 skill 让假 LLM 调用）、my-trajectory.test.tsx
  （轨迹面板 slot 玩法红绿翻转）、my-turns.test.ts（projectTurns 断言红绿翻转）——
  三个练习均已实测全绿。
