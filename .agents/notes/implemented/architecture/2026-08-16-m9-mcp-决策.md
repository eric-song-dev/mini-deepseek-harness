# M9 决策：MCP 外部工具桥（mcp-client）

- **日期**：2026-08-16
- **状态**：`implemented`（M9 完成并验收；上游调研见同目录 `2026-08-16-m9-上游调研.md`）

## 背景

原 backlog #6"MCP、LSP"的 MCP 部分（LSP 继续留 backlog）。目标：外部 MCP server 的
工具成为 mini Tools 注册表里的普通工具，`agent loop` 一行不改。开工前按协议读完
上游必读索引 11 项（见调研 note），spec 定稿后 TDD 实现。

## 决策（逐条，与 spec 对照）

1. **包形态**：新包 `@mini-dsh/mcp`，namespace 插件（`name='mcp-client'`、
   `inject=['tools']`，无 default export）——沿用上游"不造独立服务键"。一个插件
   实例 = 一个 MCP server；N 个 server = profile 里 N 行同插件不同 config。
2. **SDK**：`@modelcontextprotocol/sdk` ^1.30.0（唯一 MCP 依赖；server 半边
   McpServer 用于 fixture）。不手写 JSON-RPC。
3. **配置落点（排期遗留拍板）**：profile.yml 插件行 `options`——kernel 零改动；
   环境变量只是 `env` 字段的数据源。mini 手写 `resolveConfig`（无 schemastery）：
   serverName 正则、只许 stdio、**拒绝未知字段**（防拼写错误被静默忽略）、缺省补默认。
4. **命名**：`publicToolName` = `mcp__<server>__<raw>`，非法字符替换 `_`，超长（>64）
   报错。**裁剪上游的 hash 后缀分支**——安全论证：注册表重名必抛 + swap 冲突整代回滚，
   规范化碰撞绝不静默损坏，只可能响亮地少一组工具。
5. **两阶段同步**：fetch（cursor 分页攒新一代，失败不碰注册表）→ swap（先撤销旧代
   再注册新代，冲突回滚整代）。**纳入 list_changed 重同步**（无重同步则"失败保留旧代"
   验收无路可测）；重同步失败 catch 后保留旧代 + error 日志。
6. **执行语义**：executor 闭包持有 rawName（公开名绝不发服务器）；text 块 `\n`
   连接、非文本块占位符（上游同款文案）；**isError:true 是结果不是异常**（返回
   `{ isError: true, content }`，与 bash exit code / skill {error} 同款纪律），仅
   transport 级失败 throw（loop crash 路径）；input 非对象兜底 `{}`。
7. **生命周期**：初始 connect/同步失败恒 throw（fail-fast——`failOnStartupError`
   二态裁剪）；`onclose`（子进程退出）→ **断开即撤销**全部工具（比上游"保留死工具
   直到重连"更简单，M6 教学点）；重连 = dispose 后重新装载（公开名是纯函数，名字
   重建相同）；`onerror` 接住 SDK 对非零退出的 McpError（实施中实测：不接住变未处理
   异常）；dispose = 注销 + 关连接 + 释放 serverName。自动重连监督器砍。
8. **测试分层**（上游同款分层）：`McpClientLike` 窄接口 → 假 client 单测纯逻辑；
   `vi.mock` SDK 测插件生命周期；e2e 真 stdio（fixture server + 官方
   server-filesystem 互操作）。
9. **fixture/练习 server 写纯 JS `.mjs`**：node 直跑零构建零依赖链（顺带教学点
   "MCP server 语言/构建无关"）；用 McpServer 高层 API（zod 为 SDK 自带依赖，
   devDep 复用同一实例）。demo 与 e2e 共用 fixture。
10. **Web 接入（M8 教训的应用）**：web-demo-shared 挂 mcpClient 实例 + fake 台词本
    第二轮调 `mcp__fixture__add`——浏览器 tool 卡片可见（能力接入，client 零改动）；
    MCP 配置 UI 仍砍。

## 实施中实测出的问题（已修）

- SDK 1.30 的通知 schema 导出名是 `ToolListChangedNotificationSchema`（上游文档的
  旧名已改）；exactOptionalPropertyTypes 下 SDK 返回类型的显式 `| undefined` 联合
  需要窄接口照收；`new` mock 构造器须用普通函数（箭头函数不可构造）。
- filesystem server 的 `.bin` shim 是 shell 脚本：须直接作为 `command` 交给系统执行
  （上游 e2e 同款），用 node 包一层会把它当 JS 解析。
