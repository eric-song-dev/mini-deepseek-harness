## 照搬的概念（mini seam 契约）

1. **架构本质**：MCP 只是"工具生产者"。namespace 插件 `name='mcp-client'`、
   `inject=['tools']`、无 default export；一个插件实例 = 一个 MCP server（N 个 server
   = 加载 N 个同名不同 config 的实例）。不造独立服务键。SDK 用官方
   `@modelcontextprotocol/sdk`（Client + StdioClientTransport；demo/测试 fixture 用
   McpServer + StdioServerTransport 半边）。
2. **两个名字**：`rawName` 只走 wire（`tools/call`）；公开名
   `mcp__<serverName>__<rawName>` 注册进 `ctx.tools`，是 `(serverName, rawName)` 的
   纯函数，绝不解析公开名还原 rawName。
3. **serverName**：本地稳定配置（不是远端 `serverInfo.name`——不可信、跨部署不唯一、
   升级会变）；`^[A-Za-z0-9_-]{1,32}`；跨存活实例唯一，重复 = 后加载实例启动失败、
   前实例无损。上游用 `WeakMap<Context, Set>` 按 ctx.root 预留 + ctx.effect 释放，mini 同款。
4. **两阶段同步**：fetch 阶段分页 `listTools`（cursor 循环）攒齐新一代定义，任何失败
   不碰注册表（旧代原样）；swap 阶段先 dispose 旧代再逐个 register，register 冲突
   （只可能是外部抢占 `mcp__<serverName>__` 命名空间）回滚整代（绝不半套）。
   服务器同一工具名重复列出 = 无效工具列表 → fetch 阶段抛错。
5. **注册物是原始定义**：MCP 的 JSON Schema 与 description 原样透传，只换模型可见 name，
   无 `defineTool` DSL 转换；之后自动流入现有执行管线（上游 ToolRuntime 断言
   "Raw JSON-Schema tool definitions (from MCP servers) are still accepted by
   `register()` directly"）。
6. **执行语义**：executor 闭包持有 rawName；`client.callTool({name: rawName, arguments})`；
   text 块 `\n` 连接、image/audio/resource/未知块 → 占位符（上游文案
   `[image: image/png, content discarded]` 等）；`isError:true` 走错误路径；
   input 非对象（模型给裸 JSON 值）→ 兜底 `{}` 让服务器给出具体缺参错误。
7. **生命周期**：apply 阻塞在初始 connect + 发现（工具在 fiber 激活前注册完毕）；
   `notifications/tools/list_changed` → 重同步（fetch 失败保留旧代）；
   stdio 子进程退出 → SDK `client.onclose`；dispose = 关连接 + 注销全部 + 释放
   serverName（HMR-safety：相同 serverName 重建出完全相同的公开名）。

## 本 session 新增核实细节

- **SDK 版本**：registry 最新 `@modelcontextprotocol/sdk` 1.30.0（engines node>=18，
  本机 22.19 满足；deps 含 zod——mini 只在 fixture 用 SDK 的低层
  `server.server.registerTool()`（raw JSON Schema），**不引入 zod**）。
  官方 server-filesystem 最新 2026.7.10（e2e devDep）。
- **上游 unit/e2e 分层**：单元测 mock SDK（命名算法、代切换/回滚、重同步失败保留旧代、
  结果映射、配置校验）；e2e 用仓库内 fixture server + 官方 server-everything/filesystem
  真协议零 key。mini 照此分层：fake `McpClientLike` 接口做 sync/executor 单测，
  `vi.mock` SDK 做插件生命周期单测，真 stdio 做 e2e。
- **fixture 形态**：上游 fixture-server.ts 用 `tsx` 生态跑 TS。mini 的 fixture 写成
  **纯 JS `.mjs`**（`node fixture-server.mjs` 直跑、零构建零依赖链），也是教程练习的
  模板（练习服务器同样 .mjs）——顺带教学点："MCP server 就是一个说 JSON-RPC 的程序，
  语言/构建无关"。
- **上游 `apply` 显式 async**：连接+初始发现是 startup work，cordis 会 await。
  mini 同样 async apply（cordis 4.0.0-rc.8 实测 await async setup，M6/M8 已有先例）。

## 逐条裁剪核对（draft"裁剪决定"→ 定稿结论）

| draft 条目 | 定稿结论 |
|---|---|
| 只做 stdio transport | **保留**。Streamable HTTP 砍。 |
| 官方 SDK Client/StdioClientTransport | **保留**。 |
| 注册进现有 Tools 注册表 | **保留**（`Tool.declaration`：name=公开名、description 透传、parameters=inputSchema 透传）。 |
| 两阶段同步 | **保留**，并**纳入 list_changed 重同步**——没有重同步，"失败保留旧代"验收无路可测（初始同步没有旧代）。单测覆盖重同步失败/回滚，e2e 只做真协议 happy path。 |
| 断开即撤销 + 手动重连 | **保留**（比上游"保留死工具直到重连"更简单，M6 教学点；`client.onclose` → 全部 off()）。重连 = dispose 后重新 apply（HMR-safety 测试守护"可重连重注册"）。自动重连监督器砍。 |
| 公开名 hash 规范化砍 | **保留砍**：非法字符替换 `_` + 超长（>64）**报错**（不截断）。安全论证：mini 注册表重名必抛、同步冲突整代回滚，规范化碰撞绝不静默损坏，只可能"响亮地少一组工具"；hash 是产品级细节。 |
| failOnStartupError 二态砍 | **保留砍**：初始 connect/同步失败**恒 throw**（插件启动失败，fail-fast 教学更直白）。 |
| env 不 scrub（`{...process.env, ...config.env}`） | **保留**（教程注明上游为何 scrub 及 mini 的取舍）。 |
| resources/prompts/OAuth/outputSchema/structuredContent 砍 | **保留**：结果只投影文本；structuredContent 丢弃。 |
| invariants 伴生砍 | **保留**（上游 invariant.ts 是空安装器，无运行时行为）。 |
| MCP 配置 UI 砍 | **保留**。但按 M8 教训补 **Web 能力接入路径**：web-demo-shared 挂 mcpClient 实例（fixture server）+ fake 台词本第二轮调用 `mcp__fixture__add`——浏览器 tool 卡片可见，demo:web 有 M9 验收路径。 |
| signal 取消透传 | 上游 `exec.signal` → `$/cancelRequest`；mini ToolContext 无 signal（不改 seam），**砍**，SDK 默认 60s 超时兜底。 |
| toolCallTimeoutMs 配置 | **砍**（config 里没有；SDK 默认 60s）。 |

## 定稿拍板（排期 note 遗留问题）

- **mcp server 配置落点**：profile.yml 插件行的 `options`（`{ name: '@mini-dsh/mcp',
  options: { serverName, command, args... } }`）——kernel 零改动，与"一切皆为插件"最一致。
  环境变量不是配置落点，只是 `env` 字段的数据源。
- **MCP isError 语义**（上游 throw → ToolRuntime 错误路径）：mini 走"异常是结果"纪律
  （bash 的 exit code、skill 的 {error} 同款）——`isError:true` 返回
  `{ isError: true, content: text }` 结果对象让模型看到失败原因自行纠正；仅 transport
  级失败（未连接等）throw → loop crash 路径（轨迹可见）。
- **demo/e2e 共用 fixture server**：`packages/mcp/examples/fixture-server.mjs`（add/greet/
  echo/image/admin.reset/crash），e2e 再加官方 server-filesystem 互操作证明。
