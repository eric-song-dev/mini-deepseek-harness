## 照搬的概念（mini seam 契约的直接来源）

1. **subagents = 具名 provider 注册表**（`ctx.subagents`）：同 LLM 适配器注册表模式，
   多提供方共存按名路由（`registerProvider / getProvider / list / start(name, request)`）。
   与 bash 的"每 ctx 单执行器"形成对照——教学点：多实现 seam vs 单实现 seam。
2. **`SubagentProvider`**：`name` + `inheritsParentContext`（spawn=false / fork=true，
   **只描述"子 agent 看不看父已完成轮次"**，不暗示工具/权限继承）+ `start()`。
3. **单次 run 的语义边界**（最重要的契约）：
   - `start()` 兑现 = 子 agent 已发布（mini：子会话已建好 + agentLoop 已装好）；
     start 拒绝 = 未发布资源已清理、**不 emit 生命周期事件对**。
   - **`SubagentRun.result` 失败不 reject**：子级失败以非 `completed` 的 `stopReason`
     resolve（`completed|aborted|error|max-tokens|refusal`，可合并扩展）；只有无法表示
     的基础设施故障才 reject。非 completed → 消费方映射为 isError 工具结果。
   - `run.id` == 子会话 id（本地 run）；`dispose()` 幂等。
4. **输出选取规则**：`SubagentResult.output` = 最后一条**非空** assistant 消息内容；
   没有非空 assistant 则空（上游还有"累计流回退"，mini 简化不照搬）。
5. **事件只观察不落父日志**：`subagent/start`/`subagent/end` 成对（同 runId+provider+
   childId；end 带 stopReason + 最后 assistant 输出）、`subagent/provider-added`/
   `provider-removed` 是注册表事件。上游 start/end 是 **scope-filtered**（carrier 键 =
   委派父级）；mini 的对应物：**emit 在父会话 ctx 的隔离事件总线上**（Session 构造器
   给每个会话独立 EventsService，M1 已有）——父级作用域监听器只看得到自己的委派，
   语义等价、零新机制。
6. **spawn / fork 的差异只有"初始内容"**：共用同一个 `startInProcessRun(request,
   {seed?})` 五步驱动器（深度→建子 agent→未发布设置窗口→发布+followup→读结果）。
   spawn 不传 seed（空对话开始）；fork 的 seed = 父日志的**平衡已完成轮次前缀**
   （截至最后一个 `turn/end`、seq 从 0 连续；无已完成轮次时为空 = 等价 spawn）。
   mini 对应：fork 的 seed = 父日志 `slice(0, lastTurnEnd.seq)`。
7. **子 agent 获得全新扁平作用域**：不继承父的工具限制/权限；mini 天然成立（子会话
   ctx 继承的是**根** ctx 的 llm/tools，M0 cordis 继承链）。父会话污染最小：一次运行
   绝不写父会话，父只通过工具结果看到 output。
8. **tool-subagent 跟随 provider 生命周期**：provider-added 时挂工具、provider-removed
   时摘（sibling 加载顺序无关、HMR 替换安全）；前台调用 = `await run.result` +
   **总是** `await run.dispose()`；只有 `completed` 返回规范值
   `{ kind:'foreground', runId, output }`，非 completed → isError 且**保留子 agent 的
   部分输出文本**（截断回答绝不冒充成功、也绝不静默丢弃）。
9. **workflow = subagents 之上的消费方**：脚本每次 `agent()` = 一次
   `ctx.subagents.start()`；上游 `tool-ralph` 证明"同一引擎 + subagents"可承载专用编排
   策略而**不改 agent loop**——mini 该学的分层（workflowEngine 服务 + tool-workflow
   消费方，脚本钩子固定走 spawn/fork 提供方）。
10. **workflow 失败纪律（fatal 语义）**：脚本钩子误用（坏参数、未知/延迟的 agent()
    选项、坏 schema、超上限、seam 启动失败、取消）抛 `fatal: true` 的 `WorkflowError`；
    `parallel()`/`pipeline()` 对 fatal **直接 re-throw**（拼错选项必须终止脚本），
    逐项 `null` 只留给"子 run 失败（非 completed stop reason）+ 阶段内普通脚本错误"。
11. **workflow 事件 payload 以 `WorkflowRunInfo(id+meta)` 开头**；`workflow/end` **刻意
    省略 result value**（观察者不得拿到调用方 result 的可变别名）；
    `workflow/agent-start/end` 按 `agent.seq` 配对；监听器异常被隔离（记录日志、
    不传播、不阻断后续监听器）。
12. **workflow run 契约**：`result` **从不 reject**（脚本失败 → `stopReason:'error'`）；
    `cancel()` + 幂等 `dispose()`；meta/args 是纯 JSON 数据，**引擎绝不通过对脚本文本
    求值获取它们**；脚本 parse 先行（坏脚本在任何 agent 启动前失败）。
13. **工具描述即脚本编写契约**：tool-workflow 的 description 全文规定了 meta 块、五个
    钩子语义、"误用钩子必杀脚本"、约束（不注入 fs/网络/timer，脚本只做协调）。

## 砍掉的复杂度（M8 不做，留 backlog）

- 进程外协议全家（acp/codex/claude-code/dsh-sdk）、**worker-thread 隔离**（mini 同线程
  `async Function` 执行脚本；注释与教程注明"同线程 ≠ 沙箱"）；
- 可继续后台 subagent 全家（startContinuable/followup/interrupt/reportFrom/register-
  ContinuableSetup/冷恢复/结算通知/subagent-descriptor 投影目录）；
- 能力矩阵与委派策略（outputSchema/depthLimit/toolFilter/persona、
  `UNSUPPORTED_CAPABILITY` 校验、委派沙箱/审批钉定）；**深度只记账不设限**；
- 结构化输出（`structured_output` 工具 + schema 校验 + 捕获暂存）；
- 上限（maxTotalAgents / maxItemsPerCall / 并发控制）与 Task 后台形态；
- `tool-subagent-control` / `tool-subagent-report`（父↔子消息通道）；
- UI 全量（ui-subagent 目录树 / ui-workflow-run Chat 节点）与 tool-workflow 的持久
  `tool-workflow/*` 日志记录（父日志只多 tool 调用/结果事件，子会话经 meta.parentSessionId
  + 会话列表导航回放）；
- fork 的可继续路径（上游自身也因前缀复用问题把 fork 钉在 one-shot）。

## 定稿拍板（写入 M8 spec 的关键决定，含 1 处 draft 修订）

1. **fork 纳入 M8**（draft 留的拍板）：~30 行增量（completedTurnPrefix + provider +
   工具措辞切换），让 `inheritsParentContext` 非平凡、seed 语义可被假 LLM 断言
   （子 agent 第一次模型调用看到的 messages 含父历史）——教学价值兑现。
2. **mini 的 `parent: Agent` 就是父会话 ctx**（draft 修订）：mini 没有上游 Agent 服务，
   loop 是唯一知道"当前会话"的组件；`ToolContext` 增可选 `agent?: Context`（tools
   包类型演进，无行为变化），loop 传 `{ cwd, agent: ctx }`（**一行透传**）。provider 从
   parent ctx 读 `session-log`（fork 种子）/`session-meta`（谱系/cwd/depth），观察事件
   emit 在 parent ctx（隔离总线）。上游同款理由：loop 为每次模型驱动的工具调用设置
   exec.agent。**验收措辞修订**：draft 的"agent loop 一行不改"改为
   "loop 无任何 subagent/workflow 专属逻辑，仅 ToolContext 透传一行"。
3. **stopReason 词汇**：mini 用 `'completed'|'aborted'|'error'`（draft 已裁），
   turn/end 映射：done→completed，limit/crash→error；aborted 仅来自启动前 signal 中止
   （mini loop 无中途取消——已知限制，注释注明）。
4. **子会话 meta 记谱系**：`SessionMeta`/`CreateSessionInput` 增可选 `parentSessionId`
   + `depth`（旧会话缺省 = 顶层）；fork 种子经 `create({ seed })` 持久化（JSONL 头记录
   占 seq 1，种子 seq 平移 +1，manager 负责重编号；resume 重放同前缀）。
5. **观察事件 emit 位置**：`subagent/*` 与 `workflow/*` 一律 emit 在**父会话 ctx**
   （隔离总线 → 不落父日志、天然按父级作用域过滤）；`subagent/provider-added/removed`
   是注册表事件，emit 在服务 ctx（根）。
6. **包布局**：新 `packages/subagent/`（seam + spawn/fork 提供方 + tool-subagent）与
   `packages/workflow/`（workflowEngine + tool-workflow）；tools 包 +agent 类型字段；
   session 包 +谱系/seed；agent 包 loop 一行；vitest node workspace 收新包；
   bundle-web 不接（M8 验收不含 Web 演示，子会话经现有会话列表即可回放）。
