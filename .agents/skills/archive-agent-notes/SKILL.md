# 归档 mini-deepseek-harness 的 Agent Notes

压缩活跃决策语料，但不抹掉还能指导工作的历史。逐份语义判断；字数与年龄只是发现线索，绝不是归档标准。

## 先读契约

分类之前先读 [.agents/notes/README.md](../../.agents/notes/README.md)（目录约定、记录格式、跨 session 工作流）。用当前代码、配置、包 README、更新的 note 与入链来确定一条理由现在是否还拥有或约束任何东西。

## 新增 note 时查取代

每份新 note 都触发一次对"覆盖同一决策、机制或被否方案"的活跃 note 的范围审计。写新 note 的同时分类每份完整或部分取代：完整取代的 implemented note 同一次变更归档；部分取代或独立有用的理由保留并交叉链接；过时的 proposal 用诚实理由 reject；不再防止可信错误的 rejected note 删除。新拥有者吸收了每条独特命题时应用合并规则；已知匹配不要推迟到下次语料审计。

## 按未来价值分类

应用这些生命周期专属的结果：

- **Implemented — 保持活跃**：note 的理由、备选方案、否定保证、持久/wire 语义、所有权边界、安全规则或重新引入条件可能指导未来变更时保留。长度无关。
- **Implemented — 归档**：已交付决策完整且正文不太可能指导未来工作——一次性 UI 细节、窄适配器、小闭环 bug、被取代的实现细节、当前行为在别处已然显然的过程历史。
- **Proposed — 永不归档**：活跃提案保持活跃；不值得再追时用诚实理由 reject 并满足 rejected 生命周期格式。
- **Rejected — 只作为护栏保留**：只有当失败的提案仍然是一个诱人且后果严重的错误、且 note 解释了它为什么输时才保留。
- **Rejected — 删除**：被否想法过时、被取代、不再可信、或不可能防止再次争论时删除整份。修复或删除入链。

不要为了配额归档。范围内每份都检查，相似组归到同一条原则下分类，接近的案子用最佳判断，真正临界的决策记进交接。

## 校准示例

这些例子设定标准；字数证明大小不是测试。

**归档**已实现 note 如：

- 折叠的侧栏控制轨 —— 已闭环的次要 UI 行为；
- 命令参数适配器 —— 大量实现细节，几乎没有未来设计杠杆；
- 文档图谱工具 —— 已完成的文档机制，当前生成器即权威。

**保留**已实现 note 如：

- 事件溯源会话 —— 基础权威与持久性边界；
- 会话目录与身份策略 —— 持久存储与身份政策；
- 注册即 effect（M6）—— 持续约束每个未来 seam 的所有权规则；
- 等待多模态落地的图像内容块决策 —— 因为它陈述了协调的重新引入条件。

**Rejected**：

- 保留"合并某个包拆分"——合并的诱惑仍然存在；
- 删除"通过工具调用流式传递工作流进度"——其前提已被后来的决策解决。

## 归档一份 implemented note

1. 把整份 `YYYY-MM-DD-<主题>.md` 从 `implemented/<分类>/` 移到 `archived/<分类>/`（归档路径里**没有** `implemented` 这一层）。
2. 不改正文。只在 `Status: implemented` 下面插入一行 `Archived: YYYY-MM-DD`（归档日期）。
3. 搜索活跃文字里的入链。改指到当前权威、只在意引用历史快照时指向归档路径、或删除。绝不修归档 note 自己的出链。
4. 同步 `.agents/notes/README.md` 的指针（若归档的正是它引用的那份）。

归档后永不编辑、移动、翻译、重排或删除。归档 note 仍然是合法入链目标，但只是历史快照，不是当前行为的权威。

## 验证与报告

跑相关检查（若归档影响教程/README 引用则跑对应练习与 `pnpm typecheck`）；选择任何额外证据走 [pre-push-checks](../pre-push-checks/SKILL.md)。

报告：保留的活跃 implemented note、归档的 implemented note、保留/删除的 rejected note、被拒的 proposed note（如有），以及每个真正临界的案子与它的字数和选定结果。不要声称归档 note 的出链有效——归档纪律本就不检查它们。
