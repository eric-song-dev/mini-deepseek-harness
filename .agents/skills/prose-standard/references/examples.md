# 行文范例（蒸馏）

用这些例子识别支配原则，不当文本模板。"平衡"= 在该位置用最少的解释保住每个承重命题。

## 保住每个事实性分句

**原句**：『协调器按会话串行化写入、dispose 前排空缓冲事件、并把后端失败报告给调用方。』

**过度修剪**：『协调器串行化持久化。』

**平衡**：保留原句。

删除装饰与重复，不删命题。主体、按会话的范围、dispose 顺序、失败可见性——是四个独立的事实。

## 显式技能范围是功能性的

**过度修剪**：『读事实来源，用判断。』

**平衡**：『本技能是引导，不是完整清单。在列出的检查之外使用判断；文档化的要求仍然适用。』

**过度详细**：几段文字论证为什么清单替代不了独立推理。

保留显式限制，因为它改变 agent 应用工作流的方式。修剪重复的劝说，不修剪护栏。

## 教程/演练保留动作与验证

**过度修剪**：『给这个工具加测试。』

**平衡**：『在单元层测注册与撤销，通过真实入口路径（demo/启动器）演练一次工具，输出变化时加快照。验证断言观察的是外部结果而不是模型的自述。』

**过度详细**：对每个 fixture 文件与断言的走查（示例代码里已经可见）。

保留测试层级、必需动作、真实入口路径与可观察验证。删 fixture 叙事。

## 保留所有权与时机

**过度修剪**：『卸载时取消 provider 的工作。』

**平衡**：『运行时在释放子作用域前请求取消；provider 仍然负责在 dispose 完成前汇合自己的 worker。』

**过度详细**：按时间顺序叙述实现 teardown 用到的每个 promise 与回调。

主体、顺序、所有权交接点、完成保证——是不同的事实性分句。

## 事件 JSDoc 保留边界时机

**过度修剪**：『组合并缓存会话前缀。』

**平衡**：『在首个 pre-step 与模型请求前组合一次会话前缀。监听器追加进当前请求，pre-step 压力核算收到组合后的前缀。』

事件顺序及其对当前请求的后果是调用方可见行为，不是实现叙事。

## 给复杂代码定向，不复述它

**过度修剪**：『worker 域支持。』

**平衡**：『拥有 worker 域与它的宿主桥。域初始化只发生一次；dispose 终止 worker 并拒绝之后的调用。协议理由见 worker 隔离 note。』

**过度详细**：对下面每个类与辅助函数逐段的预告。

保留模块的角色、依赖、职责与非显然的生命周期行为。链接架构理由，让代码展示局部控制流。

## 公开 JSDoc 包含失败

**过度修剪**：『返回域全局对象。』

**平衡**：『返回已初始化的域全局对象。初始化未完成或域已 dispose 时抛错。』

**过度详细**：导致每个抛错的内部状态机分支与确切的辅助调用。

抛错与状态前置条件是调用方可见的契约事实。

## 保留精炼的实现映射

**过度修剪**：『外部 API 支撑的搜索 provider。』

**平衡**：『把每个 provider 结果映射到共享的搜索结果字段，保留标题、URL 与正文，省略仅属于该 provider 的排名元数据。』

**过度详细**：逐字段复述映射代码（含同名且赋值显然的字段）。

保留解释适配器在哪里丢弃或改变信息的映射细节。

## 链接理由的同时保留本地契约

**过度修剪**：『dispose 记录在生命周期 note 里。』

**平衡**：『dispose 中止运行并等待 provider 静默。所有权与竞态处理见生命周期 note。』

**过度详细**：在每个 disposer 旁复述 note 的 promise 编排与被否决的所有权模型。

把行为与完成保证放在调用方需要的地方。算法与理由积极链接；链接不能替代本地契约。

## 已实现 note 保留验证契约

**过度修剪**：因为 note 已交付而删掉整个测试小节。

**平衡**：『单元测试覆盖发布前与发布后的取消、dispose 静默、provider 重载。构建产物冒烟覆盖真实入口路径；快照覆盖推迟，因为传输是进程专属的。』

**过度详细**：对 fixture 与断言逐文件走查，没有新的行为区分。

删迁移任务与测试叙事。保留层级、它们钉住的行为、真实入口路径与指名覆盖缺口。

## 安全边界可以有一个具体例子

**过度修剪**：『挂载的插件共享宿主权限。』

**平衡**：『挂载的插件共享宿主权限；例如拿到 `ctx.shell` 就能以宿主执行器的权限执行命令。』

**过度详细**：列出插件能滥用的每个服务与每个假想利用。

当一个例子让抽象的边界变得可操作时保留它。

## 推理过程整体删除

**过度详细**：『首先循环检查值是否缺省。如果缺省，下一个分支提前返回。否则继续，这就是最终断言安全的原因。』

**平衡**：代码已经表达这些分支时，不加注释。如果提前返回保护的是一个非显然不变量，只陈述那个不变量。

不要把推理过程压缩成更短的叙事；删掉它。

## 配置注释解释配置树表达不了的东西

**过度详细**：『这一行加载本地 filesystem 提供方，接着是 policy 插件，接着是读、写、编辑工具，』而相邻条目已经展示了这个顺序。

**平衡**：『policy 要在模型可见工具之前加载，让它们的 write/edit 调用穿过读前变更门。』

保留顺序的后果、令人意外的范围规则或安全边界。让配置展示它自己的清单。

## 不要只为了字数修剪

**当前**：『适配器把 provider 错误转成共享错误类型，让调用方统一处理认证、限流与瞬时失败。』

**更短但更差**：『适配器规范化 provider 错误。』

**平衡决策**：除非链接或周边契约已列出失败类别，否则保留当前句。更短的版本丢了后果与区分，结构也没变好。

## 模型可见文案遵循所有权

**过度修剪**：『调用失败时工具返回错误。』

**过度详细**：把另一个包的 schema 与渲染器字符串复制进本后端 README。

**平衡**：引用本包拥有的稳定 prompt、结果与错误文案。schema 链接生成的工具目录，别的包拥有的文案链接消费方 README；本地只陈述本包的条件或差异。

到达模型的措辞是行为，但重复仍然会漂移。精确性属于拥有方。

## 生成的摘要必须独立成立

**过度修剪**：『审批请求与策略服务。』拥有方后面才解释策略顺序与审计日志，但目录只导出第一句。

**过度详细**：把服务的完整生命周期与 prompt 通知行为搬进被抽取的句子。

**平衡**：『应用会话策略并在每个 ask/outcome 对记入请求会话日志的审批服务。』非目录细节留在后续句子里。

知道生成器抽取什么。那个片段必须保住它的生成输出上所需的契约。

## 限制是契约，不是债务清单

**过度修剪**：漏掉一个进程生命周期的缓存——它让配置变更需要插件重载。

**过度详细**：列出私有辅助清理与仅测试用的访问器，没有调用方或维护者后果。

**平衡**：『provider 选择在插件生命期内缓存；安装或修复 provider 需要重载。』普通清理留在 TODO 或 note 里。

保留影响使用或安全维护的缺口与非显然约束。包 README 不是 backlog 倾倒场。
