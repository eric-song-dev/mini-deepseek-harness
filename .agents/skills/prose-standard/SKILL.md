# mini-deepseek-harness 行文标准

写够保住契约的长度，然后删掉推理过程、重复与装饰。契约 = 调用方、被调方、实现方、生产方或消费方依赖的一项义务、不变量、前置/后置条件或兼容承诺。本技能负责编辑判断与必要覆盖；用 [doc-standards](../doc-standards/SKILL.md) 决定文档放置与结构，用 [trim-cot-leakage](../trim-cot-leakage/SKILL.md) 猎杀推理过程泄漏。它是引导，不是脚本。

`contract`、`boundary`、`shape`、`surface`、`seam`、`gate`、`vocabulary` 这些词是使用前要核对的术语，不是禁词。先问：确切的规则、API、字段集、类型、校验、时机点、组件拆分或失败状态，哪个陈述了这个事实；术语确指技术主题（如调用方/被调方契约、安全边界）时就保留。

注释描述代码表达不了的非显然契约或理由；不复述代码已经表明的东西。

## 输入与排除

要求显式的 `scope`（审查范围）。没有就报告缺少必要输入并停下；不要自行推断全仓库范围或开始询问式访谈。

接受 `mode: automatic | interactive`，默认 `automatic`。只有用户明确要求提问或校准才进入 interactive。

`mode` 控制提问，不控制写权限。审查与审计任务只报告发现不改文件；明确要求的写/修/剪任务才实际修改。

始终把 `node_modules/`、`.git/`、`shots/`（录制快照）排除在发现、审查与编辑之外，即使范围是整个仓库。排除规则放在包含 glob 之后，防止后面的 include 把它们重新纳入：例如 ripgrep 命令以 `--glob '!node_modules/**'` 结尾。

`.agents/notes/archived/` 是冻结快照，排除在行文审查与编辑之外；只有理解历史引证时才精确地查一个目标，绝不现代化它的措辞或出链。

生成的目录、快照与 fixture 视为派生物：先改拥有它们的源或场景，再重新生成产物。

## 保住完整命题

编辑前，先枚举段落里的每个命题，保留下述每一条相关项：

- 主体与动作；
- 条件、时机与顺序；
- 模态（必须/可以/绝不）；
- 否定保证与例外；
- 所有权、副作用、失败模式与后果。

只有每个事实性分句都存活且结果更清晰时，才删形容词、重复与叙事。字数变少本身不是改进。

在使用点保留完整的本地契约：调用方或维护者当场需要的行为、失败、所有权与后果。架构、理由、算法、历史或扩展示例**积极链接**到拥有它们的文档——一个解释只有一个家；关键契约事实可以在本地重复。

省略它可能导致误用或错误简化的非显然理由要保留；否则只陈述后果并链接理由的家。

## 各位置的必要覆盖

这不是单向缩减。当代码、类型与结构没有表达出下述必要契约时，要补回文字；事实已在本地显然可见时不要加注释。

- **公开 JSDoc**：记录调用方可见的返回区分、抛错/拒绝、副作用、所有权、时机、取消与持久性。
- **内部注释**：为非局部的结构和显然复杂的局部结构定向，包括不变量、竞态顺序、所有权、安全边界与令人意外的失败行为。删除控制流叙事与代码复述。
- **模块注释**：陈述模块的角色、依赖、职责与非显然的架构选择；把架构选择链接到拥有它的解释。
- **测试**：只解释非显然的测试设计——为什么用这个 fixture、断言、平台适配、真实入口路径或间接观察。删除走查与清单。
- **README**：包含消费方契约：配置、语义、失败、限制、扩展点与模型可见效果。引用本包拥有的稳定模型可见文案；跨包内容链接到拥有方。
- **Agent Notes**（`.agents/notes/`）：保留独有理由、机制、备选方案、后果、交付验证证据与指名覆盖缺口。已实现的 note 用现在时陈述交付现实；删除计划清单，保留钉住决策的证据。
- **技能与 agent 指令**：陈述行为护栏与显式范围限制（如"引导，不是脚本/清单"）。工作流保持精炼并链接事实来源。
- **示例与配置注释**：解释访问限制、非显然的接线或加载顺序、安全姿态、回放行为、例外与可能的误用。不复述配置已经展示的条目。
- **prompt 与可见文案**：措辞就是行为。检查生成输出并运行行为验证，或说明为何不适用快照。
- **诊断信息**：命名失败的主体或路径、被违反的规则，以及非显然时的纠正方式。删除内部执行叙事。

## 工作流

1. 确认范围、模式与当前分支/基线。不检查无关分支。
2. 判断一段文字前先读拥有它的代码或文档（requirements、spec、包 README）。需要校准或不熟悉的场景读 [examples.md](references/examples.md)。
3. 检查被请求的范围，而不只是最大的文件。用搜索与字数找候选，再逐段语义判断。
4. 每个候选归类为 keep / add / trim / restore / restructure / defer。只有任务授权编辑时才实际修改；不要为了凑删除目标而制造编辑。
5. 先改拥有者再改派生物。学到新规则后复查类似段落。
6. 跑相关的窄检查（`pnpm vitest run <文件>`、`pnpm typecheck`、`git diff --check`，涉及可见文案的跑行为测试）。核实最终 diff 里没有 `node_modules/` 路径。
7. 报告：检查过的范围、明确改动、刻意保留、推迟项与实际跑过的检查。

## 临界决策

只有当至少两个版本都满足完整命题规则、但交换了公认原则、且本技能尚未裁决这个取舍时，一个案子才是临界（borderline）。只有一个保住命题的答案的重写不叫临界。

automatic 模式下：授权的就应用明确编辑，真正的临界案例如实报告而不提问。不要为了推进而削弱一个命题。

interactive 模式下：把类似段落归到同一个支配原则下，给出两三个可行版本、推荐一个、说明事实或结构差异。用户决定后，把原则与版本蒸馏进 [examples.md](references/examples.md)（不带会话历史与审查者叙事），并把学到的规则应用到范围内的每个类似段落。
