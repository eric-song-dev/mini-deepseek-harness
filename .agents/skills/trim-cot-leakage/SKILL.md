# 修剪思维链（CoT）泄漏

思维链泄漏 = 视角停留在写作会话而不是仓库的文字：它引证只有那个会话看得到的工件，叙述的是变更而不是状态，或与已经离开的审查者争辩。修复永远不是单纯的删除——段落带着事实分句时，把每条改写成在 HEAD 处成立的样子，再删掉周围的记录；一条事实都没有的（审计编号、控制流叙事）整体删除。**必需背景**：[prose-standard](../prose-standard/SKILL.md) 拥有本技能应用的"完整命题"规则；引证规则的理由由 [code-review](../code-review/SKILL.md) 的"证据真实存在"承接。本技能是引导，不是脚本。

## 唯一测试

对每个可疑段落问：**一个站在 HEAD 处的读者，接触不到任何会话记录、PR 讨论串或未提交草稿，能解析每个引用、验证每个断言吗？** 不能 → 把存活的事实从仓库视角重述，删掉其余。能 → 就不是泄漏，无论它听上去多像历史——但"可解析"只过本技能这一关：在讲当前状态的表面（README、docs、JSDoc）上，可解析的变更故事仍然是变更叙事。

## 分类学

1. **死设计会话引证**——`(决策 7)`、`(审计 C2)`、`设计 §4.7`、`计划 §1.4`、阶段标签（`T4`、`W3`、`P-I`）、"设计台账"、"(B 裁决)"。如果决策有已提交的拥有者，按名字与路径引用它；否则删除引证并把事实分句改写成独立成立。
2. **Stack 与 PR 视角**——"这个 stack 后面的 PR"、"本 PR 新增"、"上一个 commit"。陈述已交付的机制或扩展点；推迟的工作移到 `TODO` 标记或 issue 引用。
3. **变更叙事与版本戳**——"以前""不再""旧的 X"、索引式戳记（"v1""这一版""今天"与过去状态对照）。陈述当前行为；修好的回归变成现在时反事实（"没有 X，Y 就会发生"），绝不是仓库历史（"以前会 Y"）。
4. **审查编排**——"审查中被拒：""审查者确认过"、草稿序数（"本 note 的 v5"）、轮次归属。把存活的决策与理由当普通事实保留；删除谁在何时说的。
5. **对审查者说话的自证**——"这个 cast 是安全的——它就是……""这是对的，因为……"。为自证正确性而写的注释是在回应审查者，不是维护者。陈述让代码安全的不变量；代码已经展示时就删注释。
6. **复述与推导记录**——控制流叙事（"先 X，然后 Y"）、测试走查、显然分支的证明。删除；只保留非显然契约或不变量。
7. **迟疑与计划残留**——"目前大概没问题""应该够了"、没有标记的推迟。升级为 `TODO`/`FIXME` 或重述为实际边界；删除迟疑。
8. **写作语言滑移**——在中文文档里残留的英文工作片段，或反之（如"端"、`---- 私有 ----` 分隔线）。翻译或删除。

## 什么不是泄漏

无辅助的删除在两个方向都会失败：删掉持久引用、留下死引用。按下述保留规则执行；[examples.md](references/examples.md) 校准每个规则：

- **Issue 引用**——`#1470`、`TODO(名字):`、"issue #N 拥有后续"在 HEAD 处可解析；任何表面都保留，包括 README。不要搬进 notes。
- **Notes 与复盘里的已合并 PR/issue 引证**——被文档标准认可的变更故事路由。
- **抑制理由**——`// 禁用规则 -- 原因`、覆盖率忽略理由、空 catch 的解释是必需文字；理由错了就修，绝不删。
- **现在时反事实回归钉**——"没有 X，Y 就会发生"、"天真的 X 会……"。
- **实测边界**——"（实测：512 层嵌套 ≈ 0.15s）"校准一个常量；"实测"二字是承重的出处标记。
- **运行时新旧状态**——"旧连接先排空，新连接再接受"是运行时生命周期，不是变更历史。
- **note 变更故事小节里的历史阶段名**——"第一版交付了 X"在那里是安全的；索引式戳记（"这一版"）哪里都禁用。
- **仓库外按设计可解析的外部引用**——标准章节（RFC 9110 §10.1.5）；§-禁令只针对未提交的内部草稿。
- **项目口吻与体裁形式**——"我们"作为项目口吻；note 的"备选方案"小节。

## 工作流

1. 范围与排除按 [prose-standard](../prose-standard/SKILL.md)：要求显式 scope；绝不碰 `node_modules/`、`.git/`、`shots/`、`.agents/notes/archived/` 与录制快照——录制的模型输出与封存历史保持原口吻。
2. 先只读审计：跑 [recall batteries](references/recall-batteries.md)（加 `--hidden` 搜到 `.agents/`），再逐条语义判断。探针不是定义——每轮清洗都发现探针漏掉的情况，所以还要无模式地读范围内最密的文字（模块 JSDoc、README、notes）。
3. 按表面先改拥有者：生成产物 → 改源 JSDoc 或生成器模板再重新生成；模型可见文案 → 措辞是行为，标记为需要快照支撑的变更而不是悄悄改写。
4. 删除任何东西之前，先枚举段落的命题（prose-standard）并查 [过度纠正陷阱](references/examples.md#过度纠正陷阱)：把义务剪成背书、把假设升级成已交付功能、删掉真事实、丢掉出处的修剪。
5. 验证：重跑探针，预期只剩被认可的保留、本技能自己的目录与拥有 note 的引证证据；确认每个保留引用在 HEAD 处可解析；跑触碰表面的相关检查（测试/typecheck）。
