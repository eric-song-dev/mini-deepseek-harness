# 泄漏少样本范例

从上游 2026-08 全仓清洗蒸馏而来。用它们识别支配原则，不当文本模板。本文件刻意引用泄漏措辞作为校准材料——[recall batteries](recall-batteries.md) 排除本技能目录，这些措辞不是别处的许可证。

## 死引证

### 有已提交拥有者的决策序数

**泄漏**：『Slash 输入按可见目录解析（决策 21）。』

**修复**：『Slash 输入按可见目录解析——纯文本引用决策，由 [web 输入机 note](../../../.agents/notes/implemented/architecture/2026-07-25-web-input-machine-and-slash-pipeline.md) 拥有。』

序数在 HEAD 处无处可解析；决策的名字与拥有 note 的路径可以。每个文件至少一次给出拥有 note 的路径（表面支持链接处用链接），之后的提及可以只用可搜索的名字。

### 没有拥有者的决策序数

**泄漏**：『注册表拒绝重名（决策 7：名字是平的，无命名空间）。』

**修复**：『注册表拒绝重名；名字是平的，无命名空间。』

没有已提交工件拥有"决策 7"，所以引证删除——但事实分句（平名）改写成独立成立，不随引证一起删。

### 审计条目编号

**泄漏**：『渲染是纯的：同快照同字符串（审计 R3）。』

**修复**：『渲染是纯的：同快照同字符串。』

仓库里没有审计文档；编号是零命题的会话速记。

### 未提交草稿的章节号

**泄漏**：『分层遵循设计（v2 §3.2）：`src/core/` 是纯核心。』

**修复**：『分层：`src/core/` 是纯核心。』

没人提交过的草稿的 `§N` 无处可解析。对照："按 RFC 9110 §10.1.5 转义"保留——外部标准按设计在仓库外可解析，拥有自己 §-编号的已提交文档可以按章节引用。

### 计划阶段标签

**泄漏**：『`src/client/` 是壳（T4）；P-I 迁移拥有适配器。』

**修复**：『`src/client/` 是壳；适配器在 `src/client/adapters/`。』

阶段标签索引的是一个从未落地的计划。用阶段产出替换标签。

## Stack 与 PR 视角

### 持久文字里的 stack 位置

**泄漏**：『未来的远程后端实现这个接口（沙箱后端是这个 stack 后面的 PR）。』

**修复**：『远程后端可以在不改渲染层的情况下实现这个接口。』

持久文字看不到 stack。保留扩展点契约；未完成工作的家在 PR 本身、一个 `TODO` 或 issue。

### README 里的"本 PR"

**泄漏**：『本 PR 给会话列表加了游标分页。』

**修复**：『会话列表按游标分页。』

README 活得比任何 PR 久；把机制陈述为当前事实。

## 变更叙事与版本戳

### 带 PR 号的战争故事

**泄漏**：『颜色以前来自 `--widget-*` token，没有任何东西定义它，所以一直渲染回退值；别名 token 修复了它（PR #88）。』

**修复**：『颜色来自别名 token；未定义的 token 渲染回退值。』

两个存活事实都保留——当前机制与持续存在的失败行为——用现在时重述。bug 的传记属于 PR 与它的 note。

### 删除叙事

**泄漏**：『`probe` 字段随删除那一版没了；徽章现在走通用投影对。』

**修复**：『徽章用通用投影对。』

没见过的读者从 `probe` 的缺席学不到任何东西。"现在"与已删除的过去对照就是版本戳。

### 修好的回归 → 现在时反事实

**泄漏**：『这以前会双重编码多字节标签。』

**修复**：『没有字节长度护栏，多字节标签会双重编码。』

回归钉以现在时反事实存活并点名护栏；"以前"把它钉在仓库考古上。

### 索引式版本戳

**泄漏**：『批渲染这一版是同步的；异步路径是路线图。』

**修复**：『批渲染是同步的。』（推迟放在调用点的 `TODO(名字):`。）

"这一版" / "v1" / "今天" 合并的瞬间就过期。note 变更故事小节里的历史阶段名（"第一版交付了 X"）是安全的；索引式形式永远不安全。

## 审查编排

### 审查裁决当正文

**泄漏**：『审查中被拒：缓存解析结果。我们每次调用都解析。』

**修复**（在 note 的"备选方案"里）：『**缓存解析结果。**被拒：结果依赖每次调用的 cwd，按请求键的缓存会命中过期根。』

"备选方案"体裁是被认可的家；审查者与轮次不属于理由。

### 草稿序数

**泄漏**：『截至本 note 的 v5，加载器也校验清单。』

**修复**：『加载器校验清单。』

已实现 note 陈述交付现实；它自己的修订历史在 git 里。

## 对审查者说话的自证

### 为一个 cast 辩护

**泄漏**：『这个 cast 是安全的——对象是 SDK 构造的，它只是没有把可选声明得足够严。』

**修复**：『SDK 构造这个对象时填满了每个可选字段；声明类型比运行时保证松。』

陈述维护者不能打破的不变量。"它就是……"是在回应一个 HEAD 处没人提出的异议。不变量在代码里可见时，删注释。

### 诉诸审查权威

**泄漏**：『这是对的，因为审查者确认过包裹顺序。』

**修复**：（删除；包裹顺序在函数的 `@returns` 里。）

正确性主张引用不变量或测试，绝不引用人。

## 复述与推导

### 控制流叙事

**泄漏**：『先把标签规范化，再截断它，再包裹它。』

**修复**：（删除。）

注释下面三行代码说的就是同一件事。

### 测试走查

**泄漏**：『这个测试创建会话、发两条消息、等第二条回复、然后断言日志有四条。』

**修复**：『两次往返必须恰好产生四条日志——投影去重了共享前缀。』

只保留非显然的断言理由；走查复述测试本体。

## 迟疑与计划残留

### 无标记推迟

**泄漏**：『目前先同步渲染大概没问题。』

**修复**：（删除；推迟已经有 `TODO(名字):` 标记。）

没有拥有者的迟疑是计划残留。没有标记就写一个（`TODO(名字): 每动画帧合并`），而不是保留迟疑。

### 模糊容量

**泄漏**：『64 KiB 缓冲对大多数情况应该够了。』

**修复**：『64 KiB 装得下实测最大的帧（48 KiB）并有余量；更大的帧在 `decode` 里响亮失败。』

用实际边界与超限时的失败行为替换迟疑。

## 写作语言滑移

**泄漏**：『The renderer runs on the client 端; see the 设计稿 for spacing. ---- 私有 ----』

**修复**：『渲染器跑在客户端；间距遵循设计帧 `widget-badges`。』

工作语言碎片与会话分隔线是记录残留。外部来源的名字（设计帧）保留：按设计在仓库外可解析。

## 保留

### Issue 引用在任何表面都持久

**保留**：『上限作用于完整渲染值、含包裹层（issue #1470 拥有后续）。』

一次无辅助的删除把这条删了，理由是 issue 引证该进 notes。方向反了：issue 从任何表面在 HEAD 处可解析，"#N 拥有后续"是 README 里推迟工作的被认可之家。notes 与复盘额外认可的是引用**已合并 PR** 作为证据。

### 死的点名不是"命名拥有者"

**删除**：『徽章渲染器走 widget seam（见 widget-rendering RFC）。』

一次无辅助的保留把它当作"按主题命名拥有文档"。测试标准是可解析性，不是形式：没有已提交文件回应"widget-rendering RFC"，指针是死的。有已提交拥有者就改指过去；否则删除。

### 抑制理由

**保留（修对后）**：`// 禁用下一条规则 -- 单元素字面量保证下标 0 存在。`

理由分句是必需文字。理由陈述为假（原文说"上面的循环护栏保证帧存在"，但根本没有循环）时，修理由；绝不删。

### 实测边界

**保留**：『深度上限（实测：512 层嵌套 ≈ 0.15s 同步；4096 层卡死循环）。』

实测数据把常量钉住，防止盲改；"实测"是把数据与猜测区分开的出处标记。

### 运行时新旧不是变更历史

**保留**：『旧连接先排空，新连接再接受。』

这里的"旧""新"命名的是交接中的两个活运行时对象，不是仓库状态。变更叙事禁令针对仓库历史，不是生命周期词汇。

## 过度纠正陷阱

下面的每个陷阱都在原清洗中交付过、在复查中被抓住。修剪任何东西之前先枚举段落的命题。

### 把义务剪成背书

**原文**：『这些直接注册是待迁移到 slot 的例外。』

**过度纠正**：『这些直接注册是被认可的例外。』

**正确**：『这些直接注册是待迁移到 slot 的例外。』

"待迁移"是义务；"被认可"给现状背书。修剪把句子的模态反转了。

### 把假设升级成已交付功能

**原文**：『未来的 IPC 壳子类化执行器并覆写 `spawn`。』

**过度纠正**：『IPC 壳子类化执行器并覆写 `spawn`。』

**正确**：『假设中的 IPC 壳——目前没有这样的壳——会子类化执行器并覆写 `spawn`。』

只删未来标记会把设计示意变成"这个类已交付"的宣称。显式标记假设，而不是只去掉未来式。

### 连记录一起删掉真事实

**原文**：『门禁通知叙述检查顺序；通知文案同时是 `verify-doc-typecheck` 编译的对象。』

**过度纠正**：『……』（整句当叙事删除。）

**正确**：『通知文案是 `verify-doc-typecheck` 编译的对象。』

半句是叙事；另一半是承重的耦合。命题共行时删分句，不删句子。

### 保留数字却丢掉出处

**原文**：『4 MiB 上限是实测的：最大的生成模块 3.1 MiB。』

**过度纠正**：『上限 4 MiB；最大生成模块 3.1 MiB。』

**正确**：保留"实测"。

没有"实测"，3.1 MiB 读起来像定义而不是观察结果，也不会有人在提高上限前重新测量。
